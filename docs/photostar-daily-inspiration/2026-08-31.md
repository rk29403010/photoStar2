## Best next idea — Capture Doctor

PhotoStar should distinguish **damage in the historical object** from **damage introduced while digitising it**.

For photographed/scanned prints, album pages, documents and framed photographs, detect acquisition problems such as:

- perspective/keystone distortion;
- glare and specular reflections;
- uneven lighting and shadows;
- camera shake / missed focus;
- clipped highlights or crushed shadows;
- low effective resolution;
- cropped-off borders or inscriptions;
- photographing through glass;
- duplicated/omitted pages in a capture session.

Instead of immediately trying to repair these with AI, PhotoStar should first say:

> **Better capture possible** — re-photograph this rather than restore it.

A guided recapture workflow can then show exactly what needs changing.

### Why this matters

Current mobile products such as Photomyne and Fotki already make camera capture attractive by automatically correcting perspective and lighting. PhotoStar can go further by keeping the archival distinction between the **physical source**, the **capture**, and later restoration. A capture that can cheaply be redone should not be treated like irreversible historical damage.

Photomyne: https://photomyne.com/
Fotki: https://fotki.app/

## Acquisition defects should be explicit metadata

A capture-analysis result could contain fields such as:

```text
capture_quality_v1
  perspective: moderate
  glare_regions: [...]
  blur: low
  clipping: none
  border_complete: false
  effective_resolution: 1430 px
  recommendation: recapture
```

This gives ingestion, restoration and Preservation Health a shared vocabulary.

The important classification is:

- **source defect** — scratch, tear, fading, emulsion damage;
- **capture defect** — glare, perspective, focus, lighting;
- **uncertain** — cannot reliably distinguish.

Restoration tools should preferentially fix the first class. Capture Doctor should try to eliminate the second class before restoration.

## Perspective correction is easy enough to keep deterministic

The open-source Perspec project is a useful implementation reference: it detects document/photo corners and performs perspective correction, with a CLI and a documented photo-digitisation workflow.

Official project/code: https://github.com/ad-si/Perspec

PhotoStar probably does not need Perspec itself. OpenCV-style quadrilateral detection + manual corner handles would be straightforward and keeps the operation explainable and non-generative.

## Glare is the more interesting problem

Single-image reflection removal is improving quickly, but it is precisely where PhotoStar should be conservative.

### GenSIRR — CVPR 2026

GenSIRR is a generative single-image reflection-removal system. The official release includes pretrained checkpoints, training code and a Gradio demo.

Official code: https://github.com/lime-j/GenSIRR
Official project: https://gensirr.research.mingjia.li/
Model: https://huggingface.co/lime-j/GenSIRR

This is testable, but generative reflection removal is not ideal for archival masters because it can reconstruct content behind reflections rather than recover observed evidence.

### RDNet / XReflection — CVPR 2025

RDNet won the NTIRE 2025 Single Image Reflection Removal in the Wild challenge; its authors now recommend the newer XReflection codebase for reproducibility.

Official RDNet code: https://github.com/lime-j/RDNet

No author-hosted interactive upload demo was found for RDNet.

### Adobe RAW reflection-removal research — CVPR 2025

Eric Kee, Adam Pikielny, Kevin Blackburn-Matzen and Marc Levoy demonstrated reflection removal directly in linear RAW imagery, optionally using a contextual photograph to help distinguish reflected content. The author project page includes results and presentation material, but no official reusable inference code was released.

Author project: https://erickee.com/reflections/cvpr2025.html
Paper: https://openaccess.thecvf.com/content/CVPR2025/html/Kee_Removing_Reflections_from_RAW_Photos_CVPR_2025_paper.html

The important PhotoStar lesson is that **extra capture information can make reflection removal less ambiguous**.

## Better than AI glare removal — capture two or more observations

For precious prints, PhotoStar could guide the user to make a tiny multi-shot capture:

1. phone held still;
2. photograph with light/camera geometry A;
3. slightly alter illumination/view angle;
4. photograph again;
5. align the two images;
6. identify pixels obscured by glare in one image but clean in the other;
7. build a composite only from observed pixels.

This is substantially more archival than asking a diffusion model to invent what lies behind a reflection.

For very difficult reflective surfaces, polarization-based approaches are also active research. PolarFree (CVPR 2025) provides official code, data and pretrained models, but requires polarization information and is therefore a specialist later option rather than a default phone workflow.

Official PolarFree code: https://github.com/mdyao/PolarFree
Dataset: https://huggingface.co/datasets/Mingde/PolaRGB

## UI — Scan Session rather than one-off imports

For a box/album digitisation job, PhotoStar could create a temporary **Capture Session**:

> Album 3 — 42 expected pages
>
> 37 good captures  
> 3 need recapture  
> 1 possible duplicate  
> 1 page probably missing

Each thumbnail gets only a meaningful status:

- **Good**
- **Check**
- **Recapture**

Opening a failure explains why:

> Strong glare over two faces  
> Move the light to the left and capture again.

or:

> Bottom-right corner missing  
> Move the camera slightly farther away.

This can feed directly into existing workflow/job feedback rather than becoming another independent task system.

## Live phone companion

A later low-friction version could use the phone as the camera while the desktop app acts as the archive controller.

The desktop knows which album/page is next; the phone displays only:

> Hold steady  
> ✓ focus  
> ✓ all four borders  
> ⚠ glare top-left

Then it automatically captures when the frame is acceptable and advances.

That could make high-quality digitisation dramatically less tedious while keeping the full-resolution archive local.

## Creative experiment — Reveal the object

Keep both the raw capture and corrected presentation.

A viewer could smoothly move between:

**physical object as captured** → **squared/lighting-normalised scan** → **restored photograph**

This makes the transformation history visible rather than pretending the clean digital rectangle was the original object.

For album pages and damaged prints this can be visually interesting in its own right: the user can see the photograph first as an object in the real world, then as image content.

## Best next experiment

Take about 50 deliberately imperfect photographs of real prints/album pages:

- 10 perspective errors;
- 10 glare/reflection problems;
- 10 focus/blur problems;
- 10 uneven-lighting cases;
- 10 good captures.

Build a read-only `capture_quality_v1` experiment that classifies only:

> **good / automatically correctable / recapture**

For perspective, use deterministic geometry. For glare, first detect it rather than remove it. Then test whether two deliberately varied captures can recover glare-obscured regions using alignment and observed pixels.

Only after that should GenSIRR or another single-image reflection model enter the Model Lab.

The product principle is simple:

> **If the physical original still exists, PhotoStar should prefer acquiring better evidence over inventing better pixels.**
