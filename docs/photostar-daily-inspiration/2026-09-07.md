# PhotoStar2 Daily Inspiration — 7 September 2026 — Archive Telescope

## Repo signal

`main` still has no application-code commits after 8 August 2026. The later 26 August commit is documentation-only.

Two existing design decisions make today's direction unusually well matched to the codebase:

- the grouping spec already models groups, sparse similarity edges, canonical representatives, bursts and related-image browsing;
- the gallery spec deliberately locks the normal library to one stable aspect-aware masonry layout and explicitly forbids global layout-mode switching and full-grid reshuffles.

So the opportunity is **not another gallery layout**. It is a lightweight navigation layer above the gallery.

## Best next idea — Archive Telescope

PhotoStar should let the user move through a huge archive at several levels of scale without scrolling through every thumbnail.

Think:

```text
whole archive
   ↓
decades / major islands
   ↓
events / people / places / motifs
   ↓
groups and sequences
   ↓
normal masonry gallery
   ↓
individual asset
```

At the widest view, PhotoStar might show only 30–100 representative tiles for a 50,000-image collection. Zoom or click one region and it resolves into a few hundred representatives, then finally into the existing gallery.

This should be a **navigator/minimap**, not a competing global gallery mode. The normal masonry remains stable.

**Effort:** Medium for a useful first version; high only if the visual atlas becomes very elaborate.

**User value:** Very high for large inherited archives because it changes the problem from “how do I filter 50,000 files?” to “where in the archive do I want to go?”

## Why current products point this way

Current photo managers mostly provide several orthogonal entry points rather than one genuinely scalable overview:

- Mylio offers All Photos, LifeCalendar, Map, People and Albums, with local-first storage and AI organisation: https://mylio.com/details/
- Immich currently combines timeline, map, people, albums, stacks, tags and contextual CLIP search; its search supports people, contextual content, OCR, location, time and album filters: https://immich.app/features and https://docs.immich.app/features/searching/
- Excire Foto 2027 combines a visual timeline, map, free-text search, people, visible-text search and grouping while remaining local/on-prem: https://excire.com/en/excire-foto/
- Photoreka goes furthest toward collection-scale exploration with a 2D/3D semantic atlas, infinite canvas and reports that surface recurring visual patterns: https://www.photoreka.com/

The synthesis for PhotoStar is not to copy any of those views. It is to use PhotoStar's existing family-history relationships to create **progressive semantic zoom**.

## Technical reference — PixPlot

Yale Digital Humanities Lab's PixPlot is an important precedent for collection-scale image navigation. Yale describes it as an open-source application for interactive exploration of tens of thousands to as many as a million images, placing visually similar material near each other so a collection can be inspected as a whole rather than page-by-page.

Official project/workshop page: https://dhlab.yale.edu/machine-vision-workshop/

Official code: https://github.com/YaleDHLab/pix-plot

A live cultural-heritage PixPlot example is available here: https://pixplot.smk.dk/

PixPlot's original stack is now fairly old, so I would treat it as a UI/research reference rather than a dependency.

## Current implementation reference — Plotlas

Plotlas is a newer self-hosted large-image viewer that explicitly targets collections up to one million images. It pre-bakes tile pyramids and streams only the visible tiles, supporting grid, date, category, geographic and arbitrary x/y-coordinate arrangements.

Live demo/project: https://plotlas.com/

Source repository: https://github.com/Plotlas/plotlas

This is useful for PhotoStar even if none of its code is adopted. The important architectural idea is **map-style multiresolution rendering**: wide view = coarse visual summary; zoom in = progressively sharper/more numerous images.

## Research technique — UMAP, with a warning

UMAP can project high-dimensional image embeddings to two dimensions so visually related photographs form neighbourhoods. It is actively maintained; `umap-learn` 0.5.12 was released in April 2026.

Official implementation and paper links: https://github.com/lmcinnes/umap

The official repository also documents adding new points with `transform`, which is attractive for incrementally growing libraries.

But PhotoStar should treat a 2D UMAP atlas as **navigation, not evidence**. Distances and island shapes in a projection are visualization artefacts as well as reflections of the source embedding. “Near on the map” must not silently become a family-history claim.

I found official code and extensive examples/documentation, but no single author-hosted PhotoStar-like image-library demo beyond the third-party/cultural-heritage applications above.

## Practical feature 1 — representative tiles, not every image

The first useful version does not need UMAP at all.

PhotoStar already has the concepts required to choose representatives:

- duplicate / variant canonical image;
- burst canonical;
- album/group membership;
- sparse similarity edges;
- people groups;
- eventual date/place/event metadata.

For a wide overview, recursively select representative images that maximise **coverage and diversity**, not aesthetic score.

Example:

> **1960s — 8,412 assets**
>
> 24 representative tiles showing the major people, places, events and visual clusters.

Click a wedding tile and the telescope narrows to that event; click again and the existing masonry gallery opens at that part of the collection.

**Effort:** Low-medium if based first on existing groups + date buckets.

## Practical feature 2 — Archive Minimap

Keep the normal gallery exactly as specified, but add a slim navigator beside or above it.

Possible forms:

```text
[1930s] [1940s] [1950s████] [1960s████████] [1970s██]
                   ↑ you are here
```

or a small field of representative images where the current gallery region is outlined.

The minimap can answer instantly:

- where am I in the archive?
- how much is before/after this?
- where are the dense and sparse periods?
- which major people/events dominate nearby?

This preserves the gallery's key requirement that images do not jump around as background analysis arrives.

**Effort:** Low-medium.

## Practical feature 3 — “show me another cross-section”

The same archive should be navigable through several **lenses** without changing asset truth:

- **Time** — decades → years → events
- **People** — family branches → people → co-occurrence groups
- **Place** — regions → places → viewpoints
- **Archive structure** — albums → pages / rolls → groups
- **Visual** — embedding neighbourhoods / recurring motifs

These are not five gallery modes. They are five ways to choose **where the normal gallery opens**.

This distinction makes the idea compatible with the locked gallery spec.

**Effort:** Medium, mostly navigation/query design once the underlying metadata exists.

## Creative concept — Family Motif Atlas

Once the overview works, add an optional visual lens that surfaces recurring **family motifs**, not merely identical objects.

Examples might emerge as clusters such as:

- people standing at the front door;
- birthday cakes;
- dogs on sofas;
- seaside groups;
- somebody proudly beside a new car;
- Christmas-tree photographs;
- garden portraits;
- children photographed in the same chair across generations.

These are looser than Object Threads and should therefore be labelled as **motifs / echoes**, not claims that the scene or object is the same.

This could turn thousands of ordinary photographs into a new way to see family continuity and change.

**Effort:** Medium after image embeddings exist.

## Art/design reference — the atlas as a way of thinking

Aby Warburg's *Mnemosyne Atlas* assembled 971 images across 63 surviving panels, repeatedly rearranging images to investigate visual recurrence and cultural relationships rather than forcing them into a single chronological narrative.

Official Warburg Institute resource: https://warburg.sas.ac.uk/library-collections/warburg-institute-archive/archive-collections/verknupfungszwang/mnemosyne-atlas

A more current digital-art example is Harvard's **Surprise Machines**, which used PixPlot over more than 200,000 museum objects to create unexpected visual encounters rather than conventional catalogue retrieval:

https://metalabharvard.github.io/projects/curatorial-aigents/surprisemachines/

For PhotoStar the valuable design principle is restrained: **sometimes juxtaposition reveals a family pattern that metadata did not name in advance**.

## Experimental concept — Absence becomes visible

A collection overview can reveal not only what exists but where the archive suddenly thins out.

For example:

> **1957–1960: 620 photographs**
>
> **1961–1964: 34 photographs**

That may simply reflect camera use, lost albums or undigitised material; PhotoStar should not invent an explanation.

But it can make the gap visible and connect it to Preservation Health or Living Knowledge Rescue:

> “This period is unusually sparse. Known physical album 4 may cover these years.”

or:

> “Margaret may be able to explain this missing period.”

The negative space of the archive becomes something that can be investigated.

## Best next experiment

Do **not** build a 3D atlas.

Use a representative library of at least several thousand PhotoStar assets and build one throwaway browser experiment:

1. collapse exact/variant/burst groups to their canonical representative;
2. bucket by date where known;
3. recursively select perhaps 50 representatives per level, favouring diversity rather than quality;
4. render those representatives in a simple pan/zoom or overview strip;
5. clicking a representative opens the existing masonry gallery at that group/time neighbourhood;
6. compare this with ordinary scrolling for five tasks: find a remembered event, discover an unexpected cluster, jump between decades, locate sparse periods, and return to the previous context.

Only if that feels materially better should UMAP or a Plotlas-style tiled atlas be introduced.

### Recommendation

**Explore Archive Telescope next, beginning with representative hierarchical navigation rather than semantic-map technology.**

It uses data PhotoStar already intends to compute, respects the locked masonry design, adds little ongoing user effort, and directly attacks the large-library navigation problem.

The core idea is:

> **Don't make Robin scroll through a lifetime of photographs at one fixed scale. Let the archive reveal more detail only as he moves toward it.**
