## Best next idea — Context Window

Once PhotoStar has a plausible place and date for a family photograph, offer an optional **Context** view which retrieves period-appropriate external material around it: historic maps, archival photographs, nearby buildings/streets, and modern views. Keep family evidence and external context visually and semantically separate.

Example:

- Family photo: `Cantley station, probably 1958–1962`
- Historic map: period-appropriate OS layer
- Nearby archive images: same village/station/road, preferably date-compatible
- Modern context: current map / user-supplied modern rephotograph
- Each external item retains source, date, licence and retrieval reason

The key rule is: external material can support or challenge a proposition, but does not silently become family metadata.

**User value:** high — turns an isolated family snapshot into understandable place/history without manual web research.
**Effort:** medium for a useful source-adapter prototype; higher for automatic matching/alignment.

## Why it fits PhotoStar

PR #42 gives a clean separation between an observation/evidence source and an accepted historical proposition. A Europeana or Geograph image can therefore be evidence for `probable same place` without being imported as if it belonged to the family archive. `VisualRegion` can later anchor specific comparisons such as a church tower, shop frontage or road junction.

This materially develops Place Solver rather than repeating it: Place Solver asks **where is this?**; Context Window asks **what else can we show about this place at the relevant time, and does it strengthen or weaken what we think we know?**

## UI — one contextual drawer, not another gallery

On a photo/place page:

**Context**

- `1950s map` — map layer covering the estimated date
- `Nearby in 1961` — external archival image, 180 m away
- `Same building?` — candidate visual match requiring review
- `Today` — current map / optional rephotograph

Controls: **Useful evidence · Interesting only · Wrong place · Hide source**.

For large collections, aggregate this into a Place page: `Family photographs | Historical context | Map | Stories`, with the family photographs always visually primary.

## Current products / design references

- GhostViewer (https://ghostviewer.co.uk/) is a current browser-first rephotography tool that aligns historic and modern photographs and exports then/now comparisons. Its useful lesson is lightweight alignment and keeping the old image visibly connected to the modern scene.
- Past Viewer (https://pastviewer.com/) uses a map-first historical-photo interface with era filtering and live-camera then/now comparison.
- Remiscape (https://posttrip.app/en/) uses a useful uncertainty model: exact, approximate or town-only location and year/month/decade/unknown dates. PhotoStar should preserve at least that level of spatial uncertainty rather than forcing coordinates.
- Atlas Family Archive (https://www.atlasarchive.org/) connects people, places and timelines inside a family archive. PhotoStar's differentiator should be inspectable evidence and external historical context, not merely another map.

## Source adapters worth prototyping

### Geograph Britain & Ireland
Official API: https://www.geograph.org.uk/help/api

The official API supports nearby/location searches and individual image metadata; attribution and CC BY-SA requirements are explicit. Bulk/training use should use Geograph's dumps rather than scraping or hammering the live API. For a UK family archive this is unusually practical because it can supply modern/recent views of very specific places.

### Europeana
Official APIs: https://api.europeana.eu/en

Europeana exposes Search, Record and IIIF APIs across thousands of European cultural institutions, with an official API demo. Good candidate for period photographs, artworks and documents once a place/date query exists.

### Wikimedia Commons
Official geosearch API docs: https://www.mediawiki.org/wiki/API:Geosearch
Commons API: https://commons.wikimedia.org/wiki/Commons:API/MediaWiki

The official API can retrieve media around coordinates. Useful as a broad fallback, but licensing/provenance must remain per-item.

### National Library of Scotland historic maps
Family-history maps: https://www.nls.uk/tools-for-research/family-history/maps/

NLS provides hundreds of thousands of high-resolution historic maps and over 600 georeferenced layers; its historic-map API can be embedded in other applications. This is particularly valuable for UK family photographs because map layers span the period in which many scanned family collections were made.

## Model Lab — visual place matching only after retrieval is narrowed

**AnyLoc** is an official open-source visual-place-recognition project designed to work across varied environments and viewpoints. The authors provide code, standalone demos, notebooks, a Gradio app and an official Hugging Face demo:

- Project/demo: https://anyloc.github.io/
- Official code: https://github.com/AnyLoc/AnyLoc

PhotoStar should not ask AnyLoc to search the world. A much more tractable experiment is: after metadata/map/context retrieval narrows the candidate area, can AnyLoc rank 50 nearby archive/modern images to find likely matching viewpoints?

**Mapillary Street-level Sequences (MSLS)** is an official large-scale long-term place-recognition dataset with 1.6M street-level images and official dataset/evaluation code: https://github.com/mapillary/mapillary_sls . It is useful as a benchmark resource rather than a direct PhotoStar dependency. No author-hosted family-photo-style upload demo was found.

## Practical feature — Context Suggestions queue

Do external retrieval asynchronously and only surface high-value results:

- `3 family photos may show the same building as this 1956 archive image`
- `12 photos can now be placed at least to this village`
- `Historic map contradicts current place label`
- `A modern view may be alignable with this photo`

This avoids filling every image with generic local-history trivia.

## Creative concept — Time Portal

For a strongly matched place, let the user move through three evidence layers:

`family photograph → period map/archive view → modern photograph`

Use simple alignment/swipe/opacity rather than generative animation. The emotional effect comes from genuine continuity of place. If PhotoStar has multiple family images over decades, they become intermediate layers automatically.

## Experimental concept — Context Collision

Actively look for cases where external history makes PhotoStar's current interpretation impossible or suspicious. Example: a claimed 1954 photo contains a building that archive/map evidence indicates was built in 1962, or a road alignment disappeared before the proposed date.

Treat this as a review trigger, never an automatic overwrite. This joins Background Detective, Temporal Triage and Place Solver through independent external evidence.

## Best next experiment

Choose 50 UK family photographs whose true locations are known but hide the answers from the prototype. For each, give the system only PhotoStar's existing date/person/context evidence. Prototype source adapters for NLS maps, Geograph and Wikimedia/Europeana, then test whether external retrieval can:

1. produce genuinely useful contextual material without manual web searching;
2. narrow or confirm place at town/street/building level;
3. find plausible same-view candidates;
4. avoid false confident matches;
5. preserve source/licence/date on every external item.

Only then benchmark AnyLoc for reranking the already geographically constrained candidate set.

## Recommendation

**Context Window is the best next idea to explore.** PhotoStar is already becoming good at extracting knowledge from the family's own material. The next leverage point is to connect a resolved photograph to the world around it — maps, archive photographs and today's place — while keeping external context clearly separate from family evidence.

The principle: **once PhotoStar knows roughly where and when a photograph belongs, it should be able to open a window around it in history without pretending that everything outside the family archive is automatically true.**
