The useful product problem today is not another classifier. PhotoStar is accumulating many legitimate ways to enter the same archive — time, people, places, sequences, albums, objects, evidence and visual similarity. A large archive can become harder to navigate as those dimensions multiply.

## Best next idea — Story Rivers

Add a fluid, zoomable journey view that lets a user follow one thread through a large collection while seeing where it branches into other meaningful threads.

Examples:

- Margaret → Retford → 1960s → holidays → Cromer
- Dad → cars → 1970s → same caravan → later owners
- family home → room photographs → renovations → modern rephotography

At a high level the river shows periods/places/events as broad sections. Zooming in unfolds clusters into sequences and individual photographs. Branches expose alternative routes such as a person leaving one place while another family member remains there.

This is not a graph database visualisation and should not expose every semantic edge. It is a deliberately curated navigation projection over PhotoStar's existing relationships.

**Value: high. Effort: medium for a useful 2D version; high for polished animated transitions.**

## Why this is timely

Mylio's current LifeCalendar demonstrates the value of one continuous family timeline spanning decades, with fuzzy dates, events, people and map views. Immich retains both timeline and folder navigation, and its search combines semantic search with people, locations, OCR, camera and time filters. FamilySearch Memories still largely exposes gallery/list/album/person routes. These are useful views, but they remain mostly separate modes.

PhotoStar can synthesize them differently: the user should be able to stay in one exploratory journey while the dominant organizing dimension changes naturally from time to place to person to event.

## Research inspiration — Meandering Photo Lines

The July 2026 paper **Meandering Photo Lines: Fluid Multiscale Exploration of Photographic Archives** is unusually relevant. Mark-Jan Bludau, Christian Tominski and Marian Dörk combine spatial, temporal and topical structures into adjustable meandering pathways, with animated transitions between a cluster overview and chronological photo series. Their case studies include an archive of roughly 100,000 photographs and a personal collection of roughly 20,000.

Official author/project resources:

- Project page: https://uclab.fh-potsdam.de/photolines/
- Author/institution publication page: https://uclab.fh-potsdam.de/publications/meandering-photo-lines-fluid-multiscale-exploration-of-photographic-archives
- Paper: https://arxiv.org/abs/2607.23769

The official project page includes a video demonstration. As of 30 September 2026 it explicitly says the **interactive prototype and GitHub repository will be added for IEEE VIS 2026**, so there is not yet usable official code or a public interactive prototype to integrate. Do not substitute a third-party reproduction.

The key lesson is not the river aesthetic itself. It is that **overview and detail can be the same navigational object**, rather than separate screens.

## Practical v1 — Journey Strip

Do not begin with a free-form SVG river.

Start with a horizontal Journey Strip above/beside the masonry gallery:

`1958 Retford → 1961 Cromer → 1964 new house → 1967 family event → …`

Each segment is a derived cluster. Selecting it narrows the existing gallery without replacing it. The strip can change lens:

- Time
- Person
- Place
- Event
- Object
- Source/album

The crucial interaction is **branch here**. From a 1964 family event, a user can follow Margaret, follow the place, follow the photographer's sequence, or return to the parent journey.

Keep a breadcrumb of the chosen path so exploration never becomes disorienting.

## Large-library UX — visited territory

A January 2026 cultural-heritage study on multimodal archive enrichment found that users exploring embedding-based visualisations could become lost and forget which regions they had already visited. That is directly relevant to PhotoStar.

Story Rivers should therefore remember exploration state:

- already visited sections subtly marked;
- current route always visible;
- one-click back to the branch point;
- optional `continue where I left off`;
- no forced 2D/3D embedding map.

The system should expose a human concept — a journey — rather than the geometry of its embedding index.

## Composition as a second navigation signal

Two current 2026 research projects suggest an interesting refinement: sometimes photographs relate through **how they are composed**, not merely what they depict.

**Learning visual representations for compositional analysis of artworks and photographs** (Behrad, Tuytelaars, Wagemans, August 2026) compares interpretable object-centric/spatial-graph representations with fine-tuned foundation models. It finds the interpretable approach competitive with frozen encoders, while fine-tuned foundation models perform better with enough data but lose interpretability/generalisation.

- Official paper: https://arxiv.org/abs/2608.06142
- I could not find author-provided runnable code or a usable official demo as of 30 September; code-index sites currently only offer to request code.

**VFCNet: Semantically Stable Image Composition Analysis via Saliency and Gradient Vector Flow Fusion** models composition through saliency, edges and visual-attention flow, with DINOv3 features. The authors report strong PICD composition-retrieval results.

- Paper/publisher: https://link.springer.com/chapter/10.1007/978-3-032-31666-0_35
- Author-provided code linked by the paper: https://github.com/ADadras/VFCNet
- I found official code but no author-hosted interactive demo.

PhotoStar should not score old family photographs as 'good' or 'bad' composition. A better use is a low-weight **visual-rhyme signal**: while following a journey, surface occasional photographs whose spatial arrangement echoes an earlier image even when the people/place differ.

That materially develops Family Rhymes without turning aesthetics into a quality judgement.

## Practical improvement — representative tiles with reasons

At each zoom level, choose a small number of representative photographs and explain why a tile represents the cluster when useful:

- clearest confirmed people;
- strongest accepted date/place evidence;
- visually distinctive rather than near-duplicate;
- human favourite;
- historically informative frame from a sequence.

This connects Story Rivers to Archive Telescope and Sequence Memory. The representative should be stable enough that users build spatial memory; constantly changing AI-selected covers would make the interface harder to learn.

## Creative concept — Two Lives, One River

Select two people and let PhotoStar build parallel, evidence-backed life paths:

`Margaret  ───────────────┐`
`                         ├─ shared event ──┐`
`George    ───────────────┘                 └─ separate paths`

The paths meet only where the archive has evidence connecting them: shared photographs, places, events, objects or testimony. Empty stretches remain empty.

This could make relationships visible without generating a prose biography.

## Experimental concept — The Family Current

For a whole family, build a slow, explorable flow through decades where the dominant thread changes as the archive changes: grandparents → parents → homes → holidays → later generations.

Unlike Story Cut, it is not a finished narrative. Unlike Archive Telescope, it is not a neutral overview. It is an **interactive path whose direction comes from the surviving archive and the user's choices**.

An optional external-context tributary could bring in Context Window material — historic maps or archive photographs — but it must remain visually distinct from family-source material.

## Best next experiment

Use one well-understood 5,000–20,000-photo subset and build only derived navigation data:

1. bucket by broad time;
2. identify dominant people/place/event clusters;
3. choose stable representative photographs;
4. generate branch links from existing relationships;
5. retain a visited-path history.

No new ML is required initially.

Test ten exploration tasks such as `find the period when the family moved house` or `start with Margaret and end up at Cromer without using search`.

Measure **number of navigation actions, backtracking, dead ends and whether the user can explain where they are**. If the Journey Strip reduces cognitive load, then prototype the richer meandering presentation.

## Recommendation

**Story Rivers is today's best next idea.**

PhotoStar is developing a rich semantic archive, but richness can turn into UI complexity. The next navigation layer should not expose every relationship or demand that the user choose the correct search/filter mode first.

The design rule is:

> **Let people follow one understandable thread through the archive, branch when curiosity changes direction, and always make it obvious how they got there.**
