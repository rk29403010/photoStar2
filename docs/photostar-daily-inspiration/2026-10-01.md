# PhotoStar2 Daily Inspiration — 1 October 2026 — One Good Question

## Repo signal

No new application commit has landed on `main`; it remains at `888e510`. PR #42 remains the important semantic foundation: typed entities, propositions, append-only support/oppose attestations, evidence references and explicit decisions. That makes a new capability possible without creating another metadata editor: let PhotoStar decide which *small human question* would resolve the most uncertainty.

## Best next idea — One Good Question

Instead of presenting relatives with a backlog such as “identify 1,842 unknown faces”, PhotoStar should surface one high-value question at a time:

- “Is this Betty?” — Yes / No / Not sure
- “Were these taken at the same house?” — Yes / No / Not sure
- “Was this before Margaret moved to Retford?” — Before / After / Not sure
- “Who is most likely to know about this photograph?”

The question is chosen because its answer is likely to improve *several* photographs, propositions or sequences, not merely the item on screen.

**Value:** very high. **Effort:** low-medium for a rules-based first version; medium-high for learned question selection.

The key design rule is that a human answer becomes evidence/decision material in the PR #42 model. It should never be flattened into metadata without provenance.

## Why this is different from Photo Conversations

Photo Conversations captures whatever a relative remembers. One Good Question is the inverse: PhotoStar identifies a specific uncertainty and asks the cheapest useful question needed to resolve it.

That makes the two complementary:

**open reminiscence → stories and unexpected knowledge**

**targeted question → resolve a known ambiguity**

A good session could move naturally between them.

## Practical v1 — rules, not another model

Create a ranked `QuestionCandidate` projection from existing uncertainty:

1. unresolved person proposition with two plausible identities;
2. date range whose answer would constrain a whole Sequence Memory group;
3. place proposition shared by several photographs;
4. album/verso caption whose attachment is ambiguous;
5. object recurrence whose confirmation would connect two events.

Score approximately:

`expected downstream value × uncertainty × answerability ÷ effort`

Then apply diversity so ten consecutive questions are not all face confirmations.

The UI should offer **Yes / No / Not sure / Ask someone else** wherever possible. “Not sure” is useful evidence about who knows what and prevents repeated pestering.

## Current products — prompts exist, prioritisation largely does not

Remento uses hundreds of prompts, can prompt from an uploaded photograph, and deliberately removes login/app friction for the person answering. Picturesque and Sheritage similarly attach voice stories to photographs, while Memrial emphasises collaborative confirmation of names, dates and conversation. These validate the low-friction family-contribution model.

PhotoStar’s synthesis should be different: **don’t merely choose an interesting prompt; choose the question with the highest likely archival payoff for this particular collection.**

## Research idea — active learning

This is essentially an archive-specific active-learning problem.

CVPR 2025’s *Instance-wise Supervision-level Optimization in Active Learning* (ISO) is especially relevant because it selects both **which instance to ask about** and **how expensive/precise an annotation to request**, optimising value against annotation cost while maintaining diversity. The authors provide official code at `matsuo-shinnosuke/ISOAL`; I found runnable research code but no author-hosted interactive demo.

WACV 2025’s *Active Learning for Image Segmentation with Binary User Feedback* is useful for a simpler principle: informative yes/no questions can drastically reduce human annotation burden compared with detailed annotation. The official CVF paper is available; the lead author’s publication page links the paper, but I could not find a usable author-provided code repository or interactive demo for this work.

PhotoStar does not need either ML method initially. Their useful lesson is product-level: **optimise the human’s scarce attention, not just model confidence.**

## Who should PhotoStar ask?

Add a tiny `knowledge scope` learned only from explicit contributions:

- Margaret repeatedly identifies 1950s Retford people;
- Robin knows the later houses and digitisation sources;
- another relative knows one branch of the family.

Then a question can say:

> **Best person to ask: Margaret**
> She has previously resolved 8 photographs from this period/place.

This must remain a practical routing hint, not a claim that somebody *ought* to know something.

For living contributors, keep sharing deliberately private and scoped. FamilySearch’s current guidance is a useful warning: public memories can be discoverable and reshared, while private family-group sharing requires explicit visibility choices.

## Large-library UX — Question Inbox

Do not show an intimidating “2,431 unresolved items”.

Show perhaps:

### Five useful questions

Each card states the payoff:

> **Is this Betty?**
> Could resolve 17 photographs in this face cluster.

> **Is this the Cromer house?**
> Could place 9 photographs and one film sequence.

After answering, immediately show what changed and allow undo/correction.

A five-question session should feel complete. The backlog can remain invisible unless somebody deliberately opens it.

## Creative concept — Pass the Photo

A photograph moves through the family, accumulating distinct voices rather than one canonical caption.

Robin answers a place question, then routes it to someone else for the people, who routes it again for the event. PhotoStar preserves each contribution separately:

**“That’s Aunt Betty.” — contributor A**

**“Yes, and it was taken behind the old house.” — contributor B**

**“I think this was before the wedding.” — contributor C**

This echoes community/oral-history practice: projects such as Living Memory and Goa Familia show how personal photographs become richer when people encounter them together and oral retellings are preserved alongside the images rather than collapsed into one authoritative description.

## Experimental concept — Question Cascade

A single answer can alter what PhotoStar asks next.

> “Is this Betty?” → **Yes**

Now age constraints strengthen a date range, which makes a house match plausible, which makes three adjacent Sequence Memory frames worth asking about.

So the review session becomes an adaptive investigation rather than a static form.

But cap the cascade aggressively. The goal is *less work*:

> one answer → several resolved or better-constrained propositions.

## Best next experiment

Take 100 existing unresolved propositions and manually estimate:

- answer effort (one tap / short text / voice conversation);
- uncertainty;
- number of other propositions/photos affected;
- likely knowledgeable contributor.

Build a simple deterministic ranker and compare two 20-question sessions:

**random unresolved questions vs ranked high-value questions**.

Measure **useful propositions resolved per minute**, downstream photographs improved, “not sure” rate, and repeated/annoying questions.

If the deterministic ranker wins clearly, build the Question Inbox before experimenting with learned active-learning policies.

## Recommendation

**One Good Question is the best next idea to explore.**

PhotoStar is accumulating increasingly sophisticated ways to infer things, but family archives contain knowledge that no model can recover once the people who know it are gone. The scarce resource is therefore not GPU time; it is **human memory and attention**.

The useful product principle is:

> **Don’t ask relatives to catalogue the archive. Work out the smallest question whose answer teaches PhotoStar the most.**
