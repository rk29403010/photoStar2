## Best next idea — Curate a Slice

Do not make the global readiness percentage the main game. A family archive is never really “finished”, and a single percentage collapses several different goals.

Instead let the user choose a meaningful slice and a purpose:

- Margaret · 1950–1970 → **Make identifiable**
- Album 3 → **Make story-ready**
- Unknown 1960s photos → **Make date/place useful**
- Best 200 family photos → **Make presentation-ready**
- Entire archive → **Preservation triage only**

PhotoStar then turns the newly merged readiness evidence into a finite, explainable worklist for that scope.

Example:

> **Margaret 1950–1970 — 68 photographs**
>
> 31 ready for this goal  
> 14 quick decisions  
> 11 worth investigating  
> 4 need hands-on restoration  
> 8 have insufficient evidence
>
> **Best next action:** review 6 person candidates; likely to clarify 19 photographs.

The key phrase is **for this goal**. A photograph can be ready for browsing while still having an unknown location; ready for preservation while having unidentified people; or historically useful while looking terrible.

User value: very high. Implementation effort: low-medium because PR #50 has already built most of the raw classification machinery.

## Why this is better than one readiness score

CollectionSpace's Data Preparedness Framework starts with understanding why fields are collected and what a collection needs to be ready *for*, rather than treating data cleaning as a universal checklist. Its 2025 framework is explicitly tool-agnostic and aimed at making inherited, messy cultural-heritage data manageable.

Madrona's current collections platform similarly uses non-blocking quality/readiness signals with actionable improvements rather than preventing work until every record is perfect.

TrueArchive provides a useful concrete pattern: missing-location suggestions are grouped, evidence is shown, conservative automatic rules require independent corroboration, conflicts block automation, and inferred locations cannot become reference evidence for further inference.

The PhotoStar synthesis should be: **readiness is a lens over evidence, not another truth stored about a photograph.** PR #50 already follows that technically; Curate a Slice makes the UI follow the same principle.

## Practical UI — a finite workbench

Add **Curate…** from a Person, album, event, search result, timeline range or arbitrary selection.

Choose one outcome:

- Understand it — people/date/place sufficiently useful
- Preserve it — source/provenance and serious damage reviewed
- Present it — suitable representation/enhancement chosen
- Tell its story — enough evidence/context to use in a Story Cut/Memory Bundle

Then show at most 3–5 next-action buckets. Avoid a dashboard full of percentages.

Each bucket should explain why it exists and what completing it changes. If one answer can improve several photographs, route through the One Good Question machinery rather than presenting them separately.

## Important repo improvement — readiness history, but event-based

PR #50 already records the need for a readiness-transition ledger before showing “photos improved” claims. I would implement that, but avoid snapshotting an opaque readiness score every time anything changes.

Record meaningful state transitions with cause/provenance:

- date unknown → date supported; caused by accepted album caption
- person unresolved → confirmed; contributor Robin
- appearance manual-restoration → presentation-ready; derived representation approved

Then a curation session can truthfully end with:

> **You resolved 3 questions that improved 17 photographs.**

rather than a dubious `73% → 78% ready` celebration.

## Research watch — ArchiveGPT

The 2026 peer-reviewed ArchiveGPT study evaluated VLM-generated catalogue descriptions with archive/archaeology experts and non-experts. OCR errors and hallucinations remained important quality problems, and the authors argue for human verification, provenance and transparent AI-supported cataloguing rather than autonomous replacement of curatorial judgment.

Official paper: https://www.nature.com/articles/s41599-026-08367-6
Preprint: https://arxiv.org/abs/2507.07551

I actively looked for author-provided runnable code or an interactive demo for this research and could not find one. A GitHub repository also named ArchiveGPT exists, but it is an unrelated Blue Archive chatbot framework, so it should not be treated as the research implementation.

That result supports PhotoStar's new evidence architecture particularly well: the review target should be the uncertain claim, not a wholesale AI-written description.

## Research/design watch — Expanding Perspectives

Rodriguez Echavarria and Samaroudi's 2026 work on roughly 10,000 previously unclassified Design Archives glass-plate negatives combines multimodal enrichment with 2D/3D exploration. Their evaluation found that large visualisations still need interaction support, visual cues and text search; richer 3D space alone does not make a collection understandable.

Official/author institutional publication page: https://research.brighton.ac.uk/en/publications/expanding-perspectives-to-improve-access-to-visual-archives-throu/
Paper: https://doi.org/10.1145/3771993

I could not find an author-provided public code repository or usable live demo for the system.

For PhotoStar the lesson is useful: readiness should lead to concrete subsets/actions, not become another impressive but cognitively expensive overview.

## Creative precedent — Surprise Machines

Harvard metaLAB's Surprise Machines visualises more than 200,000 Harvard Art Museums images as a similarity landscape so material normally hidden in storage becomes explorable. Unlike the two research items above, this one has both an official project page and released implementation code.

Official project: https://metalab.harvard.edu/p/surprise-machines/
Official/research-team code: https://github.com/rodighiero/surprise-machines

## Experimental concept — Dark Matter Map

Show where the archive is *poorly understood* rather than where visually similar photographs sit.

A zoomed-out timeline/person/place map could reveal areas with:

- lots of photographs but weak dates;
- faces but few identities;
- repeated places not yet connected;
- strong evidence conflicts;
- no analysis yet;
- unusually rich inscriptions/details waiting for review.

This is not a red error heatmap. Unknown material is potentially interesting, not defective.

Clicking a dark region creates a temporary Curate a Slice session:

> **1962–1967 · 143 photographs · unusually low identity coverage**
>
> Start with the 7 questions with the greatest downstream reach.

That combines archive-scale serendipity with purposeful human work.

## More creative concept — The Finished Box

Physical family-photo work has a satisfying unit that software often loses: you can finish a box or album for the day.

Let PhotoStar create a bounded session such as:

> **20 minutes · Margaret's 1960s · 8 useful decisions**

When those are done, stop. Do not immediately replace them with an infinite scroll of more chores.

The archive can still have thousands of unresolved items; the user gets a genuine stopping point and a durable record of what was improved.

This is deliberately anti-engagement design, and probably better for a preservation tool.

## Best next experiment

Use the new readiness derivation on the current real archive, but compare three interfaces without adding new AI:

1. global readiness dashboard;
2. fixed Quick wins / Investigate / Hands-on queues;
3. goal-scoped Curate a Slice for one Person/time range/album.

Give each the same 20 unresolved photographs and measure: useful decisions completed, time spent deciding what to do next, irrelevant tasks encountered, and whether the user can explain what “done” means.

Also inspect the current `readinessPercent` distribution. If it is dominated by missing dates/locations or other fields that are irrelevant to many photos, do not elevate it in the UI merely because the number now exists.

## Recommendation

**Curate a Slice is today's best next idea.**

The last 24 hours have given PhotoStar something much more valuable than another model: an evidence-oriented analysis pipeline and a deterministic way to identify what each photograph may need next. The next product step should turn that into small, meaningful, finishable pieces of work.

Design rule:

> **Don't ask whether the archive is ready. Ask what this part of the archive is ready for, and what one useful action would improve it next.**
