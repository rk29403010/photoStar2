# PhotoStar2 Daily Inspiration — 5 October 2026 — Event Desk

## Repo signal

`main` moved again on 4 October. PR #51 merged the reversible related-photo evidence network (`9bdb34e…`), followed by PR #52 (`cab05d7…`) making related-photo key ordering explicit for Sonar. The network now has bounded event hypotheses, reversible root/membership dependencies, independently grounded visual linking, local reconsideration, attributed membership decisions, targeted Refine opportunities and a genuine archive-impact ledger. Importantly, it does not start paid models in the background and does not silently turn related-photo context into truth.

This changes what is worth building next: PhotoStar can now find and reason about a *set* of related photographs, but the human-facing unit is still mostly the individual photograph/readiness view.

## Best next idea — Event Desk

Give each strong related-photo/event hypothesis a compact multi-photo investigation workspace: a contact sheet plus shared-evidence and contradiction lanes.

The question becomes not merely “what do we know about this photograph?” but “what can these photographs establish together?”

A Christmas-1976 Event Desk might show 12 candidate photographs, with badges for confirmed/strong/possible/conflicting membership and shared evidence such as decorations, room, clothing, people, sequence and independent date anchors. Selecting a shared clue highlights the exact photographs/regions that support it. Conflicts stay visible rather than being averaged away.

User value: very high now that PR #51 exists. Effort: low-medium for a read-only first version because the network already exposes membership/evidence; medium for region-level visual comparison tools.

## Practical v1

Start without another AI call:

1. Contact-sheet grid of event members, ordered by known sequence/date/filename evidence rather than arbitrary similarity.
2. Membership state on each image: anchored, strong, possible, conflicting, rejected.
3. Shared evidence lane: people, distinctive clothing, objects, buildings/room, vehicles, decorations, sequence/album/source.
4. Independent anchors lane: date/location/person facts that did not originate from this event hypothesis.
5. Contradictions lane: reliable anchors that disagree.
6. One-click “Why related?” and “Why does this matter?” provenance.
7. Human confirm/reject/undecided actions using the attributed decisions PR #51 already supports.

Do not add a single event-confidence percentage. The interesting information is *which independent roots agree and which do not*.

## Multi-photo analysis: make the board, not a giant prompt

A January 2026 paper, *More Images, More Problems?*, introduces MIMIC and finds that LVLMs commonly fail to aggregate evidence across images and to track multiple concepts as image count rises. The authors say targeted multi-image training and attention masking improve this, but the practical warning for PhotoStar is immediate: do not send 20 event photographs to a VLM and trust a fluent event summary.

Paper: https://arxiv.org/abs/2601.07812
Claimed official code: https://github.com/anurag-198/MIMIC

I could verify the paper's code URL but could not obtain a usable current official repository/demo from it today, so treat the implementation as unavailable until verified rather than assuming it can be dropped into Model Lab.

A very new paper (30 September), *Rethinking Multi-Image Re-Representation in Multi-Image Understanding*, introduces Mosaic: a visual harness that lets a model construct intermediate visual artefacts using operations such as selecting, cropping and recombining images. It reports that visual re-representation helps especially with precise comparison and hypothesis testing.

Paper: https://arxiv.org/abs/2609.39363
Official author repository: https://github.com/gengyuanmax/Mosaic

The repository exists and is author-owned, but as checked on 5 October it is empty (`size: 0`) with no released implementation or demo. So there is currently no usable official code despite the paper saying code/data will be released.

The product lesson is more valuable than the model: *re-represent the relevant evidence before reasoning*. PhotoStar can do that deterministically by assembling a small comparison board of the exact photos and regions relevant to one hypothesis.

## Model Lab experiment — evidence mosaics

Once Event Desk exists, give targeted Refine a generated evidence sheet rather than an arbitrary bag of originals:

- target photo;
- 2–4 strongest related members;
- crops around the shared object/clothing/room clue;
- literal independent anchors and their provenance;
- explicit question such as “is the red patterned curtain the same physical curtain?”

Keep the original images and region coordinates as the authoritative evidence. The mosaic is merely a disposable reasoning representation.

Test it against the existing bounded contextual Refine route. Measure correctness, token/image cost, unsupported cross-image claims and whether the model cites the correct source regions.

## Current software: useful pieces, but not this evidence model

Mylio LifeCalendar uses events as navigational time blocks and supports fuzzy dates for inherited scans. Tonfotos combines events, people, places and family relationships. Kindred auto-groups events by time/place and has a useful “Together” view for photos containing selected people. Phossil explicitly describes clustering photos from the same event/day and propagating dates from known to unknown photographs.

The synthesis for PhotoStar should be different: event membership is a *reversible hypothesis with evidence*, not a folder or automatic metadata bucket. Event Desk should expose that distinction instead of hiding it.

## Large-library UX — enter through a clue

Do not add a giant Events page as the only route. From any photograph, a small “Related evidence” control can open the Event Desk at that photograph. From a Person, Object Life, Album Grammar or Sequence Memory view, open the same desk already focused on the relevant clue.

That gives PhotoStar a useful navigation primitive:

photo → local evidence neighbourhood → event → another person/place/object/sequence

without forcing the user to understand the underlying graph.

## Art/design precedent — contact sheets as narratives

The Morgan Library & Museum's current *Hujar:Contact* exhibition (22 May–25 October 2026) draws on more than 5,700 Peter Hujar contact sheets. It describes the sheets as intimate pictorial narratives: adjacent exposures reveal interaction, selection, cropping and how a subject or situation developed.

Official exhibition: https://www.themorgan.org/exhibitions/hujar-contact

The International Center of Photography similarly describes contact sheets as exposing the process and backstory behind a selected photograph, while the London Museum catalogues contact sheets as archival objects with numbered sequences and event/place context.

The PhotoStar lesson is not to mimic a darkroom contact sheet. It is to let related photographs retain their *collective evidential meaning* instead of immediately reducing the group to one representative thumbnail.

## Creative concept — Scene Anatomy

For a well-supported event, build a non-generative “scene anatomy” from real evidence:

- wide room photograph;
- close crop of the Christmas tree;
- another frame showing the curtain/window;
- face crop identifying Margaret;
- reverse inscription or album caption;
- later rephotograph of the same room, if available.

Arrange these around a central event card with lines labelled “same curtain”, “same person”, “independent 1976 caption”, “possible same day”. Clicking any line shows why it exists.

This can be visually beautiful while remaining forensic rather than pretending to reconstruct a scene that was never photographed.

## Experimental concept — The Missing Angle

Once an event has several strongly related photographs, PhotoStar can describe what the surviving set does *not* show without generating it.

For example: “The room is seen from three directions, but no surviving frame shows the photographer's position near the doorway.” Or: “Margaret appears in every confirmed frame except the two likely taken by the same camera/operator.”

Use this only for observable coverage gaps and explicitly label inference. It could feed Photographer Solver, Archive Negative and future Stand Here Again work. Never synthesize the missing photograph.

## Best next experiment

Use 20 known multi-photo events, including several deliberately ambiguous or partially wrong groups. Build Event Desk entirely from PR #51's stored network first. Ask a human to answer five tasks: identify the strongest date anchor; find a false member; explain why two photos are related; locate a contradiction; and decide which unresolved question is worth Refine spend.

Then compare individual-photo inspection versus Event Desk. Measure time, wrong membership decisions, provenance lookups and unnecessary paid Refine calls.

Only after that test evidence mosaics with the VLM.

## Recommendation

**Event Desk is the best next idea to explore.** PR #51 has created a sophisticated reversible evidence network; the risk now is leaving that intelligence invisible and forcing the user to inspect related photos one at a time.

The product rule should be: **when the evidence is relational, show it relationally. Let the human see the photographs together, the independent anchors separately, and the contradictions without smoothing them away.**
