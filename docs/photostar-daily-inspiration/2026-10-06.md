# PhotoStar2 Daily Inspiration — 6 October 2026 — Reference Shelf

## Repo signal

There has been no newer application PR since #52 merged on 4 October. The current product direction therefore remains the evidence-oriented analysis pipeline from PR #49 plus library readiness (#50) and the reversible related-photo evidence network (#51/#52).

That combination creates a useful next boundary: PhotoStar is now good at keeping *internal* observations and contextual evidence distinct, but external historical reference material is still mostly something a person would research outside the app.

## Best next idea — Reference Shelf

Give PhotoStar a source-aware shelf of external historical exemplars that can be attached to an investigation without silently becoming family truth.

Example: a photograph contains an unfamiliar chair, dress, shopfront, telephone, car or wallpaper. Refine can search an approved reference source and return 3–8 dated exemplars. The human can inspect them beside the family photograph and, if useful, create a bounded proposition such as:

> The chair design is consistent with examples catalogued c. 1955–1965.

That is very different from:

> This photo was taken in 1960.

Every reference keeps institution, catalogue URL/identifier, catalogue date/range, rights and retrieval date. The family photograph remains the primary source; the museum/archive record is contextual evidence.

User value: high for difficult dating/place/object questions. Effort: low-medium for one-source read-only prototype; medium-high for good multi-source retrieval and rights handling.

## Why now

PR #49 deliberately keeps Scout visually independent and gives Refine bounded context. Reference Shelf fits that architecture cleanly:

1. Scout observes “patterned upholstered chair” without external hints.
2. A targeted Refine question asks whether external reference material could constrain the object.
3. Reference search happens only on demand.
4. Returned records become explicit external evidence with provenance.
5. They can support or oppose a proposition but cannot become independent observations of the family image.

That avoids the dangerous feedback loop where an AI-generated guess is searched on the web and the search result is then treated as confirmation of the original guess.

## Practical v1 — one source, one question type

Start with the V&A rather than “search the web”. Its official Collections API exposes over a million catalogue records and more than half a million images, including fashion, furniture, textiles, photography and design, with IIIF image access.

Official API: https://developers.vam.ac.uk/
Official V&A MCP trial: https://mcp.vam.ac.uk/mcp/

A useful first experiment is deliberately narrow:

> Given a human-selected object/clothing crop and a text description, retrieve dated V&A candidates that might help constrain its period.

Do not automate a date conclusion. Measure whether the retrieved exemplars actually help a human.

Europeana is a natural second source. Its official APIs expose millions of photographs plus artworks, newspapers and other cultural objects from thousands of institutions, with Search, Record and IIIF APIs.

Official APIs: https://www.europeana.eu/en/apis

For UK buildings/local context, Historic England is valuable: its archive holds more than 15 million photographs, drawings, reports and publications from the 1850s onward, with more than 1.7 million records searchable online. Rights vary, so v1 should link/embed only where permitted rather than ingesting everything.

Official archive: https://historicengland.org.uk/images-books/archive/

## UI — evidence, not shopping results

In Event Desk or a photo investigation, add:

### Reference Shelf

**V&A — evening dress, 1958–60**  
Museum catalogue date · image · why retrieved · source

**Historic England — shopfront, Norwich, 1962**  
Place/date · source

Actions:

- **Useful comparison**
- **Not relevant**
- **Supports…**
- **Opposes…**
- **Open source**

Never show “AI match 92%”. Retrieval similarity is not historical probability.

## Model Lab — AnyLoc for place references

For buildings and landscapes, test **AnyLoc**, a universal visual-place-recognition system based on DINO/DINOv2 features and VLAD aggregation.

Official author project/demo: https://anyloc.github.io/
Official author code: https://github.com/AnyLoc/AnyLoc

This is unusually testable: the authors provide a live project demo plus standalone demo scripts, Jupyter examples and a Gradio app in the official repository. It is not a historical-photo product and its benchmark domains are very different, so it should be evaluated only as candidate retrieval.

PhotoStar experiment: use a known-place reference set containing modern and historical views, then ask whether AnyLoc can retrieve the right building/location from old family photographs despite viewpoint, age, season and image degradation. Compare against existing semantic embeddings and simple local-feature matching.

The success metric is recall in the top 5–10 candidates, not autonomous geolocation accuracy.

## Current-product contrast

Timeline Scan currently estimates dates/places from clues such as handwriting, faces, clothes and cars, then lets the family check the result. Phossil similarly uses visual evidence for Bayesian date ranges rather than fake exact dates. Tonfotos focuses more on people/events/timeline navigation, while Preservo answers questions over a family's own archive with citations.

Useful pieces exist across these products, but Reference Shelf should stay distinct: it is a transparent bridge between PhotoStar's private evidence graph and *external catalogued historical objects*, with source provenance retained.

## Creative concept — Context Cabinet

For a well-understood event, PhotoStar can create a small museum-style cabinet beside the family photographs:

- the family's photograph of a 1960s sitting room;
- a V&A catalogue example of a similar chair;
- a period television/radio catalogue record;
- a Historic England photograph of the street;
- a contemporary newspaper front page from an appropriately licensed archive.

Every external object is visibly labelled **Context**, never presented as something owned by or directly connected to the family.

This makes historical context tangible without writing a generic AI essay about “life in the 1960s”.

## Experimental concept — Reference disagreement

External catalogues are not infallible and visually similar objects can span decades. Use disagreement as information.

If clothing references cluster around 1955–62 but a car model is securely documented from 1966 onward, PhotoStar should surface:

> External clues disagree. Do not narrow the date yet.

That turns Reference Shelf into another source of targeted questions rather than a date-stamping machine.

## Best next experiment

Take 50 family photographs with already-known dates/places and hide those answers.

Select 1–2 visible clues per photograph and retrieve reference exemplars from one controlled source. Compare:

- no external references;
- ordinary web/image search;
- source-aware V&A/Europeana retrieval;
- AnyLoc for the place subset.

Measure human date/place-range improvement, false confidence, useful top-5 retrieval, time per photograph and how often the external source genuinely adds information not already present internally.

## Recommendation

**Reference Shelf is the best next idea to explore.**

It materially extends the evidence architecture rather than adding another autonomous AI guesser. It also gives Context Window a disciplined implementation path: external history enters PhotoStar as inspectable, attributable evidence and remains visibly separate from family-source material.

Design rule:

> Search outward only for a specific unresolved question. Keep every external reference attached to its source, and never let resemblance masquerade as proof.
