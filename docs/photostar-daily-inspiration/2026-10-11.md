## Best next idea: Find the Photograph I Remember
Let someone type or dictate: "I'm looking for Mum beside a blue car outside a house, probably in the sixties; Joan might be there too."

Return candidates from separate evidence channels:
- hard/accepted facts: confirmed person identity, accepted date/place, album membership
- soft context: date ranges, AI Scout scene/object observations, event hypotheses
- optional visual retrieval: image-text embeddings on source images, not generative restorations
- provenance and contradictions: explain which query clauses match, are uncertain, or conflict

The parser outputs a typed, validated query plan, never raw AI-written SQL. Do not make speculative clues hard filters. Distinguish 'not known to contain Joan' from 'confirmed not Joan'. Preserve historical source identity and show one photograph per group with representations available on demand.

### UX
Editable query chips: Mum [confirmed], blue car [visual], outside house [visual], 1955–1975 [approximate], Joan [maybe]. Results are grouped: strong matches, possible matches, and promising results with missing metadata. Each result offers 'Why shown?' and 'Not this one'. A visual crop or another photograph can be added as a query exemplar.

### Practical phases and effort
1. Low-medium: deterministic search plan over existing SQLite, accepted identities, fuzzy dates, analysis observations and related-photo features. Explicit provenance per result; no new model or cloud calls.
2. Medium: evaluate local SigLIP 2 text-image retrieval against lexical and structured baselines; index each source once, with model/generation provenance and rebuildability.
3. Medium-high, optional: visual-document retrieval for scanned album pages, handwritten captions and mixed newspaper/photograph pages; test ColPali/ColQwen against OCR+FTS before adding heavier models.
4. Low: fix the documented filename-sort blank-gallery bug before expanding discovery workflows.

### Research and current products
- Immich combines contextual CLIP search with structured filters, including people, albums, OCR and date: https://docs.immich.app/features/searching/
- PhotoPrism supports structured AND/OR/NOT filters: https://docs.photoprism.app/user-guide/search/filters/
- digiKam can find images from a sketch: https://docs.digikam.org/en/left_sidebar/similarity_view.html
- MyHeritage Reimagine retains original/restored representations and supports named-person lookup: https://www.myheritage.com/help/en/articles/12852520-what-is-reimagine-and-how-can-i-use-it
- SigLIP 2: official authors' code and checkpoints https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/image_text/README_siglip2.md ; author Colab demo https://colab.research.google.com/github/google-research/big_vision/blob/main/big_vision/configs/proj/image_text/SigLIP2_demo.ipynb ; Google model https://huggingface.co/google/siglip2-base-patch16-224 . The notebook is an executable example, not a ready-made family archive UI.
- ColPali: author project code https://github.com/illuin-tech/colpali ; author-linked hosted demo https://huggingface.co/spaces/manu/ColPali-demo (reported running on Zero); paper https://arxiv.org/abs/2407.01449 . The authors now deprecate colpali-engine for new projects and recommend Sentence Transformers v6 MultiVectorEncoder. Research target: album-page/document retrieval, not ordinary snapshots.

## Creative experiment: Memory Trail
After finding a remembered photograph, optionally retain the *search journey*: "I remembered a blue car; the scan turned out to be black and white; the house was Retford, not Norwich." Save it as an attributed recollection attached to the original image, not as unquestioned metadata. It could become a narrated, source-linked mini-story for family contributors.

## Evaluation and recommendation
Build a test set of 40–60 real recollection-style questions with known target photographs, including wrong memories and missing tags. Compare existing filters, structured query plan, and optional SigLIP2. Measure recall@10, first-correct-result time, misleading claims, no-result rate and per-query cost. Keep the deterministic search interface even if embeddings fail to improve recall. Best next work: typed query-plan + explainable search results; no new model first.
