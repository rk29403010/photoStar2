## Best next idea — Words in the Scene

Use words visible **inside the photographed world** (shopfronts, street signs, bus destinations, posters, badges, newspaper headlines, product packaging) as a searchable navigation and historical investigation layer. This differs from handwriting on the back of a print and from generic object search.

Example: a faded shop sign reading `... & SONS` is recognised as an uncertain transcription with its exact image region; searching that phrase surfaces all photographs containing it, and a user can compare external business-history sources. A sign might constrain a location or date, but never establish either without corroboration.

### Small, practical first version

1. Surface existing perception `text` claims as selectable highlighted regions in the photo viewer. Keep transcription, language, confidence, source image, region coordinates and model/run version.
2. Provide a local full-text index (SQLite FTS5) over those claims, with a distinct text category (`scene`, `caption`, `inscription`, `document`) and a visible `machine suggestion` versus `human corrected` state.
3. Add a gallery `Words` lens and search-result chips: `Shop sign`, `Poster`, `Vehicle destination`, `Newspaper`. Selecting a hit zooms to the original pixels. Offer fuzzy matching but never silently rewrite the transcription.
4. Human correction is an independent assertion; re-analysis cannot erase it. Rebuildable machine indexes must not become authoritative.
5. Only after measuring coverage, benchmark dedicated OCR models on cropped regions, not entire reduced-resolution photographs. Existing photo editor's geometry and masking can help crop and rectify text non-destructively.

Estimated effort: low–medium for indexing/viewer (about 3–6 focused developer days, provisional); medium for a packaged local OCR worker (another 4–10 days depending on Windows/CPU packaging and testing). Zero API cost for the baseline, but disk and CPU cost for optional local models.

## Research / model candidates — author resources

1. **PaddleOCR (PP-OCR)** — official code https://github.com/PaddlePaddle/PaddleOCR ; official PaddlePaddle hosted demonstration https://huggingface.co/spaces/PaddlePaddle/paddleocr-3.5-transformers-demo (listed Running on Zero). Good candidate for printed signs and text regions, but test small tilted lettering.
2. **docTR** — official code https://github.com/mindee/doctr ; project-linked browser demo https://demo-doctr-tensorflowjs.mindee.com/ and local Streamlit demo in the official repo. Word-level boxes, permissive Apache-2.0 code. Browser demo page loads, interactive execution not independently tested.
3. **DeepSolo (CVPR 2023)** — official authors' code https://github.com/ViTAE-Transformer/DeepSolo ; paper https://openaccess.thecvf.com/content/CVPR2023/html/Ye_DeepSolo_Let_Transformer_Decoder_With_Explicit_Points_Solo_for_Text_CVPR_2023_paper.html . Scene text spotting for irregular signage. No verified official hosted demo; repository supplies implementation. Treat as a difficult-case comparator.
4. **LightOnOCR-3 (released 8 October 2026)** — official author announcement https://huggingface.co/blog/lightonai/lightonocr-3 ; official code https://github.com/lightonai/LightOnOCR ; official 0.8B checkpoint https://huggingface.co/lightonai/LightOnOCR-3-0.8B ; author demo https://huggingface.co/spaces/lightonai/LightOnOCR-3-Demo (listed Running on Zero). Supports OCR plus region grounding. Its reported benchmarks concern documents, **not** tiny lettering in family snapshots; 0.8B still implies a significant local runtime.

**Implementation judgement:** first expose/index the already-present perception text. If its recall is poor, compare PaddleOCR/docTR against it on scene-text crops. Do not integrate a heavyweight document model on benchmark marketing alone.

## Artistic and experimental concept — The High Street That Vanished

Make a story map of text and signs that survive incidentally in family photographs: shop names, adverts, bus destinations and handwritten price boards. Combine family originals with clearly separated Historic England / HAT references and contemporary views, without inventing a reconstruction. Let the user browse the collection as a *typographic time capsule*.

Artistic precedent: Martha Rosler's *The Bowery in two inadequate descriptive systems* deliberately juxtaposes photographs of storefronts with language, showing that neither image nor words alone fully explains social history. Artist page: https://www.martharosler.net/the-bowery-in-two-inadequate-descriptive-systems . This is a conceptual influence, not a model to copy.

Experimental extension: **A Sign's Lifespan** — cluster repeated signage across dates and locations, showing when it appeared, changed or vanished. Treat the same wording at different shops as potentially different signs, and mark historical dates as ranges. An optional `Then / Now / Evidence` triptych could reveal how a street changed.
