## Best next idea — Place Anchors

**Make a place a durable, human-verifiable entity, not just a guessed location string.** Link photographs of the same home, beach, street, school or shop across decades; connect them to historic maps and modern views. A photo taken in a house must distinguish **where the photographer stood**, **what building is depicted**, and **where the depicted scene was located**.

Example: a 1960s street photograph says "possibly Great Yarmouth" based on a bus sign. A user selects a candidate road on a historical map and marks two matching building corners. PhotoStar stores a candidate place, supporting image regions, date uncertainty and the person who confirmed it. Other photos with the same building or nearby context can then be reviewed without converting visual resemblance into proof.

### Suggested UX

- From a photo: `Investigate place` opens a split viewer: original image (with highlighted clues) + modern map + optional historical overlay + a shortlist of location hypotheses.
- Three location states: `Known place`, `Possible area` (polygon/radius), `Unlocated`; avoid a fake precise map pin for an approximate town.
- Reusable **Place Anchor**: place ID, display names/aliases, coordinates or polygon, uncertainty, valid dates, evidence/source references, and reversible human confirmations/rejections. Store camera position and view direction *separately* if established.
- **Places lens** for large libraries: clustered pins plus a time slider, and a prominent `Unplaced with clues` queue. Group by confirmed place rather than raw AI label; allow filtering `same place, different decade`.
- Batch review: when one street is confirmed, show 15 related candidates with building/sign/sequence evidence; a single human decision must not silently assign all of them.
- Start with the metadata panel and existing gallery, not a new autonomous geolocation pipeline.

### Implementation sketch / effort

1. Add place assertion and place-entity tables, including geometry/uncertainty, date scope, source links and human-vs-machine provenance; add manual `choose place` action (3–6 focused development days).
2. Add a map-sidecar viewer with `MapLibre GL JS` clustered points and an `Unplaced` filter (4–8 days). The open-source library has official docs and runnable examples: https://maplibre.org/maplibre-gl-js/docs/ and https://maplibre.org/maplibre-gl-js/docs/examples/cluster/ . Check tile provider and offline-cache licensing.
3. Generate candidate place links from confirmed place entities, observed building/sign text and sequence/album context (3–6 days). Keep proposals reversible and independently evidenced.
4. Optional historic-map layers and then/now alignment (5–10 days + licensing/integration work). No automatic geolocation model in v1.

## Model/research lab — official code and demos

1. **GeoCLIP (NeurIPS 2023)** — worldwide image-to-GPS proposals. Official authors' code https://github.com/VicenteVivan/geo-clip ; paper https://arxiv.org/abs/2309.16020 ; **official author-hosted Hugging Face demo** https://huggingface.co/spaces/VicenteVivanco/geoclip-geolocation (Space reports Running on 22 Oct; no inference verified). The authors published geoclip 1.2.3 to PyPI on 7 Oct 2026: https://pypi.org/project/geoclip/ . Important: six-decimal coordinate output is not six-decimal historical certainty. Use only as coarse suggestions and test bias on older UK family photos.
2. **AnyLoc (RA-L 2023 / ICRA 2024)** — visual place retrieval across differing views. Official authors' code https://github.com/AnyLoc/AnyLoc ; project and interactive example https://anyloc.github.io/ ; paper linked there. Official author-linked Hugging Face Space https://huggingface.co/spaces/TheProjectsGuy/AnyLoc currently reports a runtime error (insufficient hardware capacity), so **not a usable hosted upload demo today**. Useful only with a candidate reference-image collection.
3. **OpenCVL (ECCV 2026 Spotlight)** — dataset for matching ground-level imagery to aerial views. Official project and paper links https://open-cvl.github.io/ ; official authors' developer toolkit https://github.com/Open-CVL/opencvl ; sample data and official visualisations are available, but **no verified first-party hosted upload geolocator**. Dataset covers Sweden, Netherlands, Poland and Norway, not historical Norfolk; research comparator, not ready-made model.
4. **OpenCV feature matching + homography** — official code/tutorial https://docs.opencv.org/4.12.0/d1/de0/tutorial_py_feature_homography.html . Start here for human-selected building corner alignment; homography is not reliable when the 3D scene has changed substantially.

## Art and storytelling — The Street That Remembered

Photographer Irina Werning's *Back to the Future* re-enacts old family photographs in modern settings: official artist project https://irinawerning.com/gallery/back-to-the-future-thumbs/ . PhotoStar can develop a different, source-led approach: a two-track story showing a place in historical photos and in current views, with a time-slider and linked contemporary street history. Don't invent demolished buildings or substitute AI-generated history for documentary imagery.

**Experimental concept: The Vanishing Viewpoint.** Mark an approximate historical camera position, then show which lines of sight can be recreated today, which are blocked by new buildings, and which places no longer exist. Overlay the original photograph only when user-confirmed alignment exists; an optional artist's reconstruction must be conspicuously marked as interpretation. This could turn an ordinary family photo into a compelling investigation of local change.

## Benchmark / next step

Select 60 photos across five known UK places, plus 20 lookalike/distractor scenes and 20 unknown locations. Measure correct place in top-five suggestions, false confident assignments, human confirmation time, ability to represent area-level uncertainty, cross-decade retrieval, and map tile/API/privacy costs. Start with 10 manually anchored places, without adding GeoCLIP or other model dependencies. If the Places lens saves time and yields meaningful links, benchmark the models on the difficult remainder.

**Recommendation:** Build **Place Anchors + an Unplaced-with-clues review panel** first. The evidence/UX foundation is valuable even when automatic geolocation is unreliable. No cloud upload of private photos for location research without explicit opt-in.
