# PhotoStar2 Daily Inspiration — 23 October 2026
## The Date Detective: browse time without inventing dates

**Best next idea:** An uncertainty-aware **Date Detective** panel and **Time Bands** gallery, showing which evidence supports or contradicts a photograph's estimated capture period. Unlike ordinary fuzzy-date metadata, this makes dates *investigable* and lets one human correction help related photos without overwriting their source claims.

### Proposed user workflow
Select an uncertain photo and open **Why this date?**:
- "1960–1975: original visual estimate (low confidence)"
- "Before summer 1969: human-confirmed event relationship (subject to review)"
- "After 1963: independently documented building alteration (possible)"
- "Conflict: the filename says 1978; source might be a later print/scan."
Show the current supported range, alternate hypotheses and explicit unresolved conflicts. All dates here are hypothetical examples.

**Time Bands gallery**: confirmed points, supported ranges as bars, and a visible Undated lane. Filter modes must distinguish "possibly within 1960s" from "certainly within 1960s"; avoid silently sorting uncertain photos at invented midpoint dates. Deduplicate photos crossing several decade bins.

**Impact-aware review**: prioritise questions that could date many related photos, but do not treat mere album membership or similar clothes as proof of same capture date. Human decisions must be stored separately from rebuildable machine analysis.

### Implementation order and rough effort
| Feature | User value | Effort |
|---|---|---|
| Date evidence inspector on existing photo view | Explain why a date was suggested | 2–4 days |
| Time Bands / Undated lane / possible-vs-certain filter | Navigate large collections honestly | 3–6 days |
| Reversible temporal constraints + contradiction alerts | Use evidence without false precision | 4–8 days |
| Group review with before/after impact counts | Prioritise high-leverage corrections | 3–5 days |

Start with deterministic interval operations on the existing `date` claims, a separate temporal-relation table (before, after, same-exposure, same-event), and explicit evidence source IDs. A "same event" relationship may span days and must not force exact equal dates. Mark soft clues (apparent age, fashion, vehicle model) as hypotheses, not hard constraints. Do not automatically overwrite manually confirmed dates. Calibrate uncertainty later; avoid invented percentages.

### Research and technical resources
1. **Flico (2026)**: author repository [nathanaelambert/flico](https://github.com/nathanaelambert/flico) with research report, extraction code and links to a Zenodo historical image dataset of about 1.89m images. Useful as a **benchmark resource**, not an off-the-shelf dating model. Dates/labels may be noisy and collection distribution differs from family scans. **No author-hosted photo dating demo identified.**
2. **pgmpy**: [official repository](https://github.com/pgmpy/pgmpy), [official example notebooks](https://github.com/pgmpy/pgmpy/tree/dev/examples), [documentation](https://pgmpy.org/). Offers probabilistic graphical inference if PhotoStar later needs calibrated combinations of independent clues. Runnable author examples, **no verified hosted family-photo dating demo**. First avoid double-counting dependent clues (same model repeated in multiple claims).
3. **vis-timeline**: [official code](https://github.com/visjs/vis-timeline), [live project examples](https://visjs.github.io/vis-timeline/examples/timeline/). Supports date ranges, pan/zoom and interactive editing. Benchmark performance with hundreds of visible items and virtualise/aggregate for very large libraries.
4. **OR-Tools**: [official code](https://github.com/google/or-tools), [author-provided temporal constraint examples](https://github.com/google/or-tools/blob/stable/ortools/sat/docs/scheduling.md). Could handle more complex constraint graphs; overkill for first-pass interval intersection. **No dedicated hosted photo-date demo.**

### Art and experimental concept — The Time Loom
[MoMA's account of Nicholas Nixon's *The Brown Sisters*](https://www.moma.org/calendar/exhibitions/1484) illustrates how repeated family portraits make change over time visible. Build an optional **Time Loom**: select one person, room, or family home; scroll through confirmed and uncertain periods, with photos occupying honest time bands rather than fictional precise dates. Add a separately labelled rail of sourced public-history events or modern rephotographs. Gaps remain visible and meaningful. A toggle shows how accepting one dating clue would rearrange the story *before* the user commits it.

### Best experiment
Use 150 family scans across ten partially dated events. Hide 30 verified dates as an answer key. Compare existing PhotoStar date estimates with (a) deterministic evidence/interval constraints and (b) optionally pgmpy after calibration. Track fraction of true dates retained inside predicted ranges, median range width, false confident exclusions, conflicts surfaced, and human review time. **Best next build:** the read-only "Why this date?" panel and Time Bands gallery before adding inference models.
