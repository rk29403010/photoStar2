### Core user journey
User enters: **“Mum with a red pram outside a house, probably early 1970s — not the studio portraits.”** A search interpretation strip displays editable chips:
- `Person: Mum` — only a **confirmed person ID** if the user's alias is resolved; otherwise ask/select from known people.
- `Visual: red pram`, `Scene: outdoors / house` — **soft semantic matches**.
- `Date: around 1970–1975` — **soft overlap**, because the user said *probably*.
- `Exclude: studio portrait` — exclude only when there is positive evidence of studio classification; **unknown is not evidence of absence**.

Results show a compact **Why this matched** drawer: e.g. “confirmed identity”, “visual similarity”, “estimated 1968–1978 (uncertain)”, with links to the underlying image/claim. Offer **Possible near misses** for partial matches. Do not present similarity as a confirmed fact.

### Practical implementation
| Step | Benefit | Rough effort |
|---|---|---|
| Search interpretation chips, with undoable edits and an Unknown toggle | Users can correct the *search* rather than correcting archive data | 2–4 focused days |
| SQLite FTS5 over current caption/description/OCR, plus structured person/album/folder/date filters | Useful search without model downloads | 3–6 days |
| Result explanation drawer backed by claim/source IDs; uncertainty-aware filters | Inspectable matches, fewer misleading results | 3–5 days |
| Saved searches / “resume where I left off”, with stack-aware results | Makes huge libraries navigable | 2–4 days |
| Optional background image embeddings and re-ranking | Finds photos with no useful captions | 5–12 days after benchmark |

**Design:** typed search AST (`must`, `should`, `must_not`, date interval, provenance preference) compiled to parameterised SQL. Never run LLM-generated raw SQL. Combine text/metadata hits with visual similarity through transparent ranking; maintain separate confirmed vs inferred facets. Index generation/model/version should be explicit so results can be rebuilt. Respect sensitive-image restrictions; the sensitive-content detection job is still marked incomplete in the backlog, so do not send private photos to a cloud model by default.

**Important technical distinction:** the repository's 250k-face ANN follow-up concerns *face embeddings* and a measured p95 miss; it is not a validated photo-semantic-search index. A separate image-search benchmark and memory budget are required. At 250k images × 512 dimensions × float32, raw vectors alone would occupy about **512 MB** before index overhead.

### Comparative research (official documentation)
- [Immich search](https://docs.immich.app/features/searching/) combines contextual CLIP, OCR, people, filenames and metadata; the opportunity is to explain and revise *each piece of evidence* rather than just search.
- [PhotoPrism filters](https://docs.photoprism.app/user-guide/search/filters/) have AND/OR/NOT and field syntax; PhotoStar can expose equivalent power via chips instead of requiring a query language.
- [digiKam advanced search](https://docs.digikam.org/en/left_sidebar/search_view.html) and [similarity/sketch](https://docs.digikam.org/en/left_sidebar/similarity_view.html) offer metadata and visual retrieval; combine those routes in a single results surface.
- [Gramps Web](https://www.grampsweb.org/user-guide/) links media to people, events and sources; preserve genealogical identity as a verified search constraint, not an unverified visual guess.
- [Immich XMP sidecars](https://docs.immich.app/features/xmp-sidecars/) show an interoperability route for human-confirmed captions/tags. Exporting PhotoStar's full evidence graph needs a richer format; don't imply XMP can represent all claim lineage.

### Research/model lab — official code and demos
1. **[SigLIP 2](https://arxiv.org/abs/2502.14786)**: multilingual text/image retrieval, including smaller B-size variants. [Official Google research code and checkpoints](https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/image_text/README_siglip2.md); [official author-linked runnable Colab](https://colab.research.google.com/github/google-research/big_vision/blob/main/big_vision/configs/proj/image_text/SigLIP2_demo.ipynb); [official Google model weights](https://huggingface.co/google/siglip2-base-patch16-224) (Apache-2.0). Colab resource exists, but execution on old family photographs was **not verified**.
2. **[OpenCLIP](https://github.com/mlfoundations/open_clip)**: a practical configurable baseline with pretrained models and [official runnable Colab](https://colab.research.google.com/github/mlfoundations/open_clip/blob/master/docs/Interacting_with_open_clip.ipynb). Pin inference dependencies and check the chosen *weights* licence separately. No verified first-party hosted photo-library search UI.
3. **[Jina CLIP v2](https://arxiv.org/abs/2412.08802)**: higher-resolution multilingual multimodal embeddings and reduced-dimensional representations. [Official model, code examples and author-linked Colab](https://huggingface.co/jinaai/jina-clip-v2). The model is **CC BY-NC 4.0** for local download; not a straightforward commercial-distribution choice. A [Replicate playground](https://replicate.com/zsxkib/jina-clip-v2) exists but is **third-party**, not an author demo. No verified official interactive upload demo.

Benchmark on genuine scans before adopting any model: modern image-text retrieval benchmarks are not guarantees of finding faded, tiny, or historically unfamiliar details. Prefer on-device inference and no new dependency until security triage.

### Art/storytelling — The Memory Trail
[Zofia Rydet's *Sociological Record*](https://thephotographersgallery.org.uk/whats-on/zofia-rydet-sociological-record) documents thousands of domestic spaces, returning to some houses years later. [Historypin](https://www.about.historypin.org/) demonstrates connecting historical photographs, places and recollections. Synthesis: a user starts with a vague memory, then chooses **Follow this person**, **Follow this room**, **Follow this object**, or **Follow this period** from the matched photograph. The app produces a branching *Memory Trail* of authentic images, dated evidence and optional links to sourced historical context. The path is an exploration, not a generated narrative of facts. Let the user save the trail as a shareable story with citations and explicit unknowns.

**Experimental version:** two relatives independently build trails from the same photograph. PhotoStar shows where their recollections agree, differ or are missing, preserving each as an attributed memory rather than forcing one “correct” narrative. Avoid automatic public sharing.

### Best next experiment
Use **60 real user-style searches** over a representative library: 20 with confirmed identities, 20 with fuzzy visual clues, 10 with uncertain dates, and 10 containing exclusions. Measure top-5/top-20 recall, false confident matches, median time-to-find, and result explanation usefulness. Compare (A) current metadata, (B) FTS5 + structured filters, (C) optional OpenCLIP/SigLIP 2 reranking. Count **unknown fields separately** from negative evidence. Test on Windows 11 CPU-only first.

**Recommendation:** build **search interpretation chips + FTS5/structured query + Why this matched** before any model integration. This is a modest extension of an explicit backlog item, uses PhotoStar's strongest existing evidence model, and improves the usefulness of the prior daily ideas without creating yet another gallery mode.
