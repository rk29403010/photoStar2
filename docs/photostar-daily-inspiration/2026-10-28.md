# PhotoStar2 Daily Inspiration — 28 October 2026
## The Archive Firewall — decide what may leave the computer

**Best next idea:** build a single, testable local-first *outbound privacy gate* for cloud analysis, restoration and future sharing. It is not merely an NSFW classifier. The gate combines automated warnings, human decisions, destination-specific permission, and a receipt for every permitted transmission. It extends the existing sensitive-content TODO into an enforceable safety architecture rather than another gallery lens.

### Proposed UX: Processing Passport
Every asset has a compact badge: **Local only / Needs review / Allowed for [specific purpose] / Blocked**. Clicking it shows:
- What was detected locally, with uncertainty (e.g. possible nudity; a name/address visible on a document).
- What the human decided, by whom and when, with an undo action.
- Which destination and purpose is allowed: cloud metadata analysis, cloud restoration, or export to a named recipient are **different permissions**.
- The exact rendition and contextual fields that would be sent; a preview of the request is useful, but must itself stay local.
- A receipt showing destination, asset/rendition checksum, policy version, time, and result, without duplicating the original image or leaking private data into logs.

A **Cloud-ready queue** groups the collection into *unassessed*, *review needed*, *blocked*, and *eligible*. Use bulk operations only for homogeneous selections; never make a low model score equivalent to consent.

**Non-negotiable behaviour:** unknown, classifier error, stale result, changed asset/rendition or conflicting human decision => no outbound bytes. Enforce in the common network/request dispatch layer, including retries, previews, OCR crops and background jobs, not only a UI button. The current TODO's 0–25/25–75/75–100 bands should be treated as configurable review heuristics, **not calibrated probabilities or security guarantees**. Human override should not bypass destination restrictions silently.

### Practical implementation and effort (focused development estimates)
| Build | Value | Rough effort |
|---|---|---|
| Central `authorizeOutbound(request)` + deny-by-default tests | Prevents accidental disclosure across all current/future cloud jobs | 4–8 days |
| Separate `privacy_assessments`, `human_privacy_decisions`, `outbound_receipts` with model/policy/hash versioning | Preserves human corrections across re-analysis and proves what was sent | 3–5 days |
| Processing Passport badge and grouped review queue | Makes thousands of pending assets manageable | 3–6 days |
| Optional local nudity/PII screening and calibration | Reduces manual review, does not grant permission | 4–10 days plus benchmark |
| Recipient-specific export preview, metadata removal and face/name redaction | Makes family sharing safer | 4–8 days |
| Optional C2PA provenance on exported derivatives | Makes restoration/redaction history inspectable | Later, 3–6 days |

**Build the gate before the classifier.** It immediately protects the archive even if all assets initially require manual permission. No need for an additional cloud model.

### Current software and design signals
- [Immich sharing](https://docs.immich.app/features/sharing/) (official page updated **21 October 2026**) supports shared albums and public links with expiry/password options. [Immich Locked Folder](https://docs.immich.app/features/locked-folder/) hides selected images from ordinary views. Neither is a substitute for checking each cloud-analysis request.
- [PhotoPrism private photos](https://docs.photoprism.app/user-guide/organize/private/) suppress private items in search, people, places and shared albums; its [People privacy documentation](https://docs.photoprism.app/user-guide/organize/people/) distinguishes hiding a name from hiding the image. PhotoStar should treat image pixels and metadata as separately sensitive.
- [FamilySearch Memories privacy](https://www.familysearch.org/en/help/helpcenter/article/what-are-private-memories) permits private or family-group visibility and warns against sharing photographs of living people without permission. A genealogical relationship is not consent.
- [Topaz Photo cloud rendering](https://docs.topazlabs.com/topaz-photo/cloud-rendering) is explicitly an optional remote processing mode; PhotoStar's choice of restoration provider must be reflected in its outbound policy.
- [ExifTool FAQ](https://exiftool.org/faq.html) explains metadata removal and warns that indiscriminately stripping ICC profiles can damage colour fidelity. Keep originals untouched and sanitise **export copies**.

### Research and implementation lab — official code/demo status
1. **NudeNet** — [original developer's code](https://github.com/notAI-tech/NudeNet) and [developer's local/in-browser demo](https://nudenet.notai.tech/). The demo returned **502** when checked today; no working official hosted demo was verified. It detects nudity-related regions, not privacy, consent, identity, or document PII. Check the **exact code and weights licence** before packaging: repository/licence references differ from some third-party forks and PyPI distributions. A [third-party WebUI](https://github.com/maakcode/nudenet-webui) exists, not an official demo.
2. **OpenNSFW2** — [Bosco Yung's maintained Keras implementation](https://github.com/bhky/opennsfw2) of the discontinued Yahoo Open-NSFW classifier, with runnable local examples. This is **not an official maintained Yahoo release**. It provides image-level NSFW likelihood, not bounding boxes or consent. No verified first-party hosted demo found.
3. **Presidio** — [official project code, now under data-privacy-stack](https://github.com/data-privacy-stack/presidio), [official docs](https://microsoft.github.io/presidio/), [official hosted demo](https://huggingface.co/spaces/presidio/presidio_demo) (listed **Running**). OCR plus PII recognition can flag names, addresses or account details in scanned documents, but the project's own documentation warns it cannot find all PII. The demo is a research aid, **never upload private PhotoStar images to it**.
4. **C2PA / Content Credentials** — [official CAI TypeScript/Node SDK](https://github.com/contentauth/c2pa-js) and [official c2patool CLI](https://github.com/contentauth/c2patool) (Windows binaries and local runnable examples). C2PA can sign/export provenance claims; it **does not prove that a historical colourisation is accurate**, and it is not a privacy filter. Official code and runnable CLI exist; no verified official interactive upload demo was used. Notable update: the official JS SDK README says its Node v2 package was merged into this monorepo in **June 2026**; don't adopt the deprecated legacy repo.

### Art and storytelling — The Family Edition
[The Anonymous Project](https://www.anonymous-project.com/en/about), created by Lee Shulman, rescues ordinary anonymous family slides and gives them new contexts through exhibitions and storytelling. The interesting lesson is that intimate images can have public cultural value **without needing every person's identity attached**.

Experimental PhotoStar feature: a **recipient-specific Family Edition**. Select a real album or Memory Trail and preview exactly what *one particular recipient* would see: original photographs where permitted; private faces, names, GPS and captions removed or masked where necessary; evidence links kept only when safe. Create different editions for close relatives, wider family, or public historical display. Never infer that someone is happy to be shared simply because they appear in a family tree. Show a reversible side-by-side comparison of the private master and the outgoing edition; keep all redactions in derived exports, not originals.

### Benchmark / acceptance
Use 200 diverse **local-only** test images: family portraits, beach scenes, children, archival nudes/art, medical letters, gravestones, scanned documents, GPS-bearing phone images, and edited/cropped variants. Include deliberately difficult false positives and false negatives. No sensitive test image goes to any hosted demo. Test:
- **Zero outbound transmissions** for unassessed, review, blocked, changed or stale assets, including all retries and sidecar metadata.
- Model recall and false-positive review load on the locally labelled set; do not call raw scores calibrated percentages.
- Human-review time, receipt completeness, and whether permissions survive model re-runs without being broadened.
- Preview vs actual transmitted bytes/fields (hash or deterministic payload comparison).
- Metadata redaction while preserving colour profiles and archival originals.

**Best next build:** central outbound authorization with deny-by-default integration tests, followed by a small Processing Passport badge. It is more urgent than adding another AI model and gives the future search, colourisation and family-sharing ideas a trustworthy foundation.
