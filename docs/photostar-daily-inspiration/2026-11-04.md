### Best idea: Review Leverage
Instead of another chronological inbox of unidentified photographs, calculate which **single human answer could resolve the most uncertainty** across connected images. Example: confirming a person in one well-lit photograph could support several related sequences; a handwritten place name could help date an entire group. But *support* must never be silently promoted to *confirmed*: one answer is a new evidence root, not proof of every linked inference.

UI: a compact **Worth Reviewing** queue, with a representative image, proposed question, evidence, estimated number of potentially affected photos, uncertainty and **Why this question?**. Actions: Confirm / Reject / Not sure / Skip. Show observed *actual* changes after the answer using the existing impact ledger, not speculative success counts. Provide **coverage period** and distinguish newly indexed vs historically improved assets.

Ranking prototype: prioritize unreviewed clusters by (number of distinct connected assets × evidence reliability × diversity of independent evidence) / expected review time. Cap hub effects, avoid counting the same claim repeatedly, discount low-confidence links and diversify by decade/family/collection so large modern bursts don't crowd out rare historical prints. A simple SQLite query and existing graph edges can produce an initial queue; no LLM or new ANN engine required.

### Implementation plan and effort
1. Read-only candidate queue and provenance explanations: ~3–5 focused days.
2. Impact ledger presentation with coverage period and actual before/after changes: ~2–4 days.
3. Confirm/reject/unsure integration with existing reversible semantic decisions and regression tests: ~4–7 days.
4. Optional active-learning ranking after measuring human benefit: research dependent.

Test with 100 candidate questions and a held-out set of human-verified identities: measure true additional discoveries per minute, incorrect propagated inferences, repeat suggestions, and review diversity. Require no automatic identity promotions. The highest-risk failure is counting connected photographs as independently confirmed.

### Research and design references
- **Cleanlab / ActiveLab**: official source https://github.com/cleanlab/cleanlab ; paper and examples are linked in its official README. Supports label-issue detection and active-learning selection. Official runnable local examples exist; no first-party hosted interactive family-photo demo verified. Not necessary to integrate initially.
- **VIKUS Viewer**: official author code https://github.com/cpietsch/vikus-viewer and author-hosted demo https://cpietsch.github.io/vikus-viewer/ ; multi-layout exploration by time, tags and similarity. Use the idea of fluid transitions between context and details, not the entire visualization stack.
- **PixPlot**: original Yale Digital Humanities Lab project https://github.com/yaledhlab/pix-plot (and related maintained fork https://github.com/pleonard212/pix-plot ); visual clustering of thousands of images. A working official interactive demo was not verified. This suggests a later spatial overview of unresolved clusters.
- **CollectionBuilder**: official project https://collectionbuilder.github.io/ and source https://github.com/CollectionBuilder/collectionbuilder-gh ; static collection exhibitions with timelines, maps and search. Useful for lightweight exports of reviewed stories, not a replacement for PhotoStar's database.
- **digiKam** https://docs.digikam.org/en/left_sidebar/people_view.html and **Immich** https://docs.immich.app/features/facial-recognition/ : conventional suggested/confirmed face workflows. PhotoStar can differentiate by ranking questions according to *cross-photo evidence gain* rather than merely grouping faces.
- **Tropy** https://docs.tropy.org/in-the-item-view/selections and **Gramps Web** https://www.grampsweb.org/features/ : region-specific archival notes and genealogical context respectively; useful corroboration sources.

### Creative experiment: The Discovery Constellation
Display a sparse visual constellation of photographs with uncertain connections. When the user answers one carefully chosen question, animate only the edges whose evidence actually changed, and reveal the newly supported paths. The aesthetic reference is archival research as an unfolding detective story, not a magical AI claiming certainty. Optional family-story export can use CollectionBuilder-style static presentations with citations and explicit unresolved gaps.

### Recommendation
Prototype the read-only **Worth Reviewing** queue on top of existing evidence features and the impact ledger. It is more valuable now than installing another recognition model: it converts PhotoStar's sophisticated but mostly invisible evidence architecture into measurable, user-directed progress.
