# PhotoStar2 Daily Inspiration — 7 November 2026
## Identity Continuity: upgrade face recognition without losing family knowledge

**Best next idea:** a read-only Face Model Migration Preview. When a better face detector or embedding model arrives, PhotoStar2 should compare the proposed new identity groups against the current ones before replacing anything. Preserve human identity decisions separately and make potential splits, merges and missing faces inspectable.

### Why now?
[PhotoPrism's 19 September 2026 release](https://github.com/photoprism/photoprism/releases) introduced improved face detection/embeddings and an explicit `faces migrate` command intended to preserve named subjects. [Its 7 October release](https://github.com/photoprism/photoprism/discussions/5893) further improved automatic naming and preserving manual corrections. This is a practical signal that model upgrades should be treated as controlled data migrations, not just background rescans.

### Feature: Face Model Migration Preview
1. Create a parallel, versioned embedding namespace (model hash, detector, alignment, preprocessing, dimensions, source crop, generation) without touching the active index.
2. Run new embeddings in a resumable job. Match old and new face regions by asset identity plus geometry; classify unchanged, new, missing, split and merged groups.
3. Present a review board: “12 named people unaffected; 3 proposed splits; 2 potential mistaken merges; 8 newly detected faces” (illustrative counts). Show before/after contact sheets and provenance for each discrepancy.
4. Transfer only explicit human decisions where region correspondence is reliable; otherwise request review. Keep old embeddings until validation and rollback checkpoint complete.
5. Switch active generation atomically, rebuild indexes, measure search p95 and record an impact ledger. Never compare raw distances between different embedding spaces.

**User value:** improved recognition without losing years of painstaking identifications. **Effort:** medium-high, roughly 1–3 weeks for a controlled prototype depending on the existing index abstraction. A read-only discrepancy report is the safer first milestone (3–6 days).

### Large-archive UX
Offer a “People → Recognition health” panel with model version, indexed faces, newly detected faces, candidate splits/merges, pending human review and actual measured search latency. Use a virtualised contact sheet to inspect changed clusters; allow manual accept/reject/unsure without overwriting the original decisions.

### Research and software
- [InsightFace official code and model zoo](https://github.com/deepinsight/insightface), [official server runnable setup](https://github.com/deepinsight/insightface/blob/master/server/README.md): ONNX recognition, model manifests and offline verification are useful design references. Official code and local runnable examples exist; no first-party public upload demo was verified. **Licensing warning:** pretrained model packs are non-commercial research only unless separately licensed; MIT source licensing does not extend to weights.
- [DeepFace author's repository](https://github.com/serengil/deepface): offers repeatable multi-model verification experiments and local API examples, plus author-linked demonstration videos. No verified first-party hosted upload demo. The wrapped models retain their own licences. Use as a research harness, not an automatic production dependency.
- [PhotoPrism release notes](https://github.com/photoprism/photoprism/releases): explicit face migration and manual correction preservation; [digiKam People View](https://docs.digikam.org/en/left_sidebar/people_view.html) provides another review-workflow reference.
- [Gramps Web](https://www.grampsweb.org/features/) shows why names and genealogical relationships are durable human records, not attributes of a particular recognition model. [Tropy](https://www.tropy.org/) offers a precedent for archival notes tied to source evidence; [darktable](https://www.darktable.org/) illustrates reversible editing history.

### Creative experiment: The Identity Drift Museum
A time-lapse exhibition of *how the archive learned who people were*, not a generated animation of their faces. Show historical family photographs in sequence with a provenance timeline: “unknown → suggested → identified by relative → corroborated by second photo → preserved through model upgrade.” Every transition is sourced and reversible. The human detective work becomes part of the family story.

### Recommended experiment
Use 1,000 face crops from an existing test collection with manually verified labels and deliberately similar relatives. Re-embed into a separate namespace; compare precision of candidate matches, false merges, false splits, new detections, review time, peak memory and p95 query latency. Require **zero loss of accepted human identity decisions** and demonstrable rollback before promoting the new generation. Do not confuse successful embedding creation with a packageable, licensed, performant deployment.

**Best next step:** implement a read-only model-diff report before choosing or installing any new face model. This develops existing PhotoStar2 evidence architecture without repeating prior feature proposals.
