# PhotoStar2 Daily Inspiration — 11 November 2026
## Archive Passport — Make family discoveries portable, not trapped in PhotoStar

**Best next idea:** Export a *portable evidence package* for a selected person, event, album or photograph: original/derived image references, captions, dated claims, region annotations, human corrections and sources. The key innovation is a **loss report** explaining what another format cannot represent.

### Feature: Archive Passport
1. Choose a photo/person/event/album. Preview a **portable packet** with a gallery of images, citations, confidence and human-versus-machine distinction.
2. Export a human-readable HTML index plus a machine-readable JSON-LD evidence graph. Add standard XMP/IPTC sidecars for interoperable descriptive fields; do not overwrite originals.
3. Region annotations can use W3C Web Annotation / IIIF selectors, with coordinates explicitly bound to the **original** image and its orientation, not a transient crop.
4. Show a **round-trip loss report**: person identities, contested claims, uncertainty intervals, AI suggestions and relationship evidence that ordinary XMP cannot encode must remain in the richer manifest.
5. Allow an offline viewer, checksum manifest and selective disclosure (living relatives, private locations, sensitive images) for sharing.

**Distinct from the 2 November preservation manifest:** this preserves *meaning, decisions and provenance*, not just file integrity.

### External research / tools
- **IPTC Photo Metadata 2025.1:** https://iptc.org/standards/photo-metadata/iptc-standard/ — standard schema for people, locations, captions, rights and 2025 AI-generation metadata; official reference files and machine-readable JSON schema. A standard, not a hosted model demo.
- **ExifTool XMP sidecars:** https://exiftool.org/metafiles.html — author-maintained runnable CLI examples, no hosted interactive demo required.
- **W3C Web Annotation:** https://www.w3.org/annotation/ — official interoperable model for evidence attached to regions; **IIIF cookbook working examples:** https://iiif.io/api/cookbook/recipe/0269-embedded-or-referenced-annotations/.
- **Tropy:** https://www.tropy.org/ — annotated archival research items; **Gramps Web:** https://www.grampsweb.org/features/ — genealogical context; **CollectionBuilder:** https://collectionbuilder.github.io/ — portable exhibition publishing; **digiKam:** https://docs.digikam.org/ — metadata and collections; **darktable:** https://www.darktable.org/ — nondestructive image versions; **Immich:** https://docs.immich.app/ — familiar photo navigation.
- **C2PA:** https://spec.c2pa.org/ — signed processing provenance can complement export, but cannot prove historical identity or original authenticity. Third-party implementation https://github.com/encypherai/encypher-c2pa has local runnable code; do not treat third-party verifier as official C2PA reference. A first-party C2PA author-hosted demo was not verified for this run.

### Creative concept — A family-history capsule
Select “Grandmother's first house” and export a self-contained interactive micro-exhibition: a few genuine photographs, a map, annotated details, dated recollections, and a visible **How do we know?** toggle. A timeline can expose contradictory memories side by side instead of synthesising a fictional consensus. The family can keep the capsule even if PhotoStar is no longer available.
