# PhotoStar2 inspiration — 13 November 2026
## One photograph, many surviving copies: the Source Lineage Workbench

**Recommendation:** build a read-only, evidence-aware *source lineage* view for photographs that have multiple scans, crops, exports, retouches, and prints. A visually similar photograph is not necessarily a duplicate, and the largest file is not necessarily the best historical source.

### Repository evidence
- GitHub commit search: main remains cab05d7c (4 October 2026), merging deterministic related-photo ordering after the reversible evidence network in PR #51.
- src/services/relatedPhotos/features.ts extracts source-linked observations, confirmed people, filename/folder context; visual features capped at 48. Do not use this retrieval index as authoritative lineage.
- docs/todo.md records a blank grouped-Justified gallery on filename sort, a 35-high/2-critical dependency audit (not rerun), and a 507.9ms p95 sqlite-vec benchmark against 150ms target.
- Existing variant stacks are mentioned in the backlog; inspect their canonical storage/relationship schema before designing migrations.
- Documentation branch currently 73 ahead/513 behind main; avoid blind merge.

### Proposed UI
Group likely versions as *Same pixels*, *Same photograph/different scan*, *Derived edit*, *Similar moment*, or *Uncertain*. Present a side-by-side aligned comparison, provenance chain and suggested roles: best documentary source, best restoration starting point, best sharing version. Never automatically delete, merge or replace originals.

A high-resolution scan with damaged edges may be a better restoration source; a smaller scan may preserve handwriting, uncropped borders or colour fidelity. Let users mark the authoritative source **for a particular purpose**, not a universal winner.

### Build path (rough engineering estimates)
1. Read-only candidate clusters from existing variant groups, SHA-256 and pHash: 2–4 days.
2. Aligned original/scan/edited comparison, including metadata and visible crop extent: 3–6 days.
3. Human-confirmed version relations, evidence provenance and reversible edits: 4–8 days.
4. Cluster browser with virtualisation, representative thumbnails and 'show all copies': 3–6 days.
5. Optional local-feature registration for different crops/rotations: 5–10 days after benchmark.

### External references
- PhotoStructure (https://photostructure.com/) and digiKam (https://www.digikam.org/) offer variant/duplicate-management precedents.
- darktable (https://www.darktable.org/) models nondestructive edit histories; Tropy (https://www.tropy.org/) models archival items with multiple views; Gramps Web (https://www.grampsweb.org/features/) motivates preserving family identity/evidence independently from file variants.
- idealo imagededup: official code https://github.com/idealo/imagededup ; official documentation and runnable local examples https://idealo.github.io/imagededup/ . No verified author-hosted interactive demo. Hashes are candidate generators, not evidence that images are interchangeable.
- Oxford VGG Image Compare: official project https://www.robots.ox.ac.uk/~vgg/software/image-compare/ ; official online browser demo https://www.robots.ox.ac.uk/~vgg/software/image-compare/app/latest/ ; original source https://gitlab.com/vgg/image-compare/ . Good model for alignment and difference inspection.
- Oxford VGG VISE: official code https://gitlab.com/vgg/vise ; project https://www.robots.ox.ac.uk/~vgg/software/vise/ ; GitHub mirror https://github.com/ox-vgg/vise . Region-based retrieval can help find differently cropped versions. No verified hosted interactive demo.
- ImageMagick official comparison examples https://imagemagick.org/compare/ support pixel difference metrics after alignment; don't interpret PSNR/SSIM as historical authenticity.

### Creative experiment — The life of a photograph
An interactive provenance strip showing a negative/print, a 1980s photocopy, a 2002 flatbed scan, a 2026 restoration and a relative's annotated copy. It tells both the pictured family's story and how the physical photograph survived, with dates and sources explicitly labelled as known or inferred.

### Evaluation
Test 200 known families of originals, rescans, edits, crops and adjacent burst frames, with difficult negatives. Measure mistaken merges (most important), source ranking, detection of missing borders/annotations, review time and performance. No destructive action. Prefer the read-only lineage workbench before another AI model.
